# Short dialogue context and state for a spoken command interpreter (state of the art as of October 2026)

Reading conventions. "(full text)" means the paper or page itself was read in this session; "(search summary)" means only a search-engine summary of the source was seen, so the number should be re-checked before it is quoted in a final report. Years are given for all pre-2024 work. All "Inferences" are mine and are not published results. Project terms used: "the bot" is the voice-commanded co-op companion (Parakeet TDT 0.6B v2 through sherpa-onnx, three DeBERTa-v3-base classifiers, rule-based place matcher and planner, CPU only).

## 1. Dialogue state tracking: what state is kept, how it is updated, and how much history matters

### Takeaway
The standard state is a small slot-value frame that is edited each turn by a handful of operations, and the published trackers that work best with little compute read only the previous turn, the current turn and the previous state; in MultiWOZ 2.1 about 96% of per-slot decisions are "carry over unchanged". The largest measured cost of keeping state is error propagation from a wrong previous state (53.01% to 81.00% joint goal accuracy when the previous state is replaced by the true one), and LLM-based tracking as of 2024 to 2026 needs 7B-plus models on GPUs.

### Cited Findings

State representations and update rules
- SOM-DST (Kim et al., ACL 2020, full text) feeds the model exactly one previous turn, the current turn and the previous dialogue state: "the size of the dialogue history is 1". The authors justify this by treating the previous state as a compact summary of the history. — [SOM-DST](https://ar5iv.labs.arxiv.org/html/1911.03906)
- SOM-DST updates each slot with one of four operations: CARRYOVER (keep the value), DELETE (set to null), DONTCARE, UPDATE (generate a new value). In the MultiWOZ 2.1 training data the operations are about 96.07% CARRYOVER, 3.74% UPDATE, 0.12% DONTCARE and 0.07% DELETE (shares computed from the paper's Table 5 counts). — [SOM-DST](https://ar5iv.labs.arxiv.org/html/1911.03906)
- SOM-DST reaches 53.01% joint goal accuracy on MultiWOZ 2.1 with BERT-base (51.72% on MultiWOZ 2.0; 53.68% and 52.32% with BERT-large) and takes 27 ms per turn (40 ms with BERT-large) on a Tesla V100 at batch size 1. No CPU figure is published. — [SOM-DST](https://ar5iv.labs.arxiv.org/html/1911.03906)
- Error propagation in SOM-DST: with the predicted previous state the accuracy is 53.01%; with the ground-truth previous state it is 81.00%; the paper says error propagation "increases the error 2.47" times and that "a relatively large amount of error comes from state operation predictor". With one of the two components (operation prediction, value generation) replaced by ground truth the accuracy is 56.37% or 89.85%; the extraction of which row is which was ambiguous in this session, and the paper's sentence implies that 89.85% is the ground-truth-operation case. — [SOM-DST](https://ar5iv.labs.arxiv.org/html/1911.03906)
- TripPy (Heck et al., SIGDIAL 2020) reports 55.29 ± 0.28% joint goal accuracy on MultiWOZ 2.1 and cites SOM-DST at 52.57% (search summary). — [TripPy](https://arxiv.org/pdf/2005.02877)
- Information-state dialogue management (TrindiKit, GoDiS, Larsson's IBiS, thesis 2002): the information state has private and shared parts; the shared part holds a stack of "questions under discussion" (QUD); a large set of update rules fires when conditions on the state hold. Elliptical utterances are interpreted as short answers to a question on the QUD, and "accommodation" rules (tacit moves, not tied to an utterance) move a question from the dialogue plan onto the QUD when the user answers a question that has not been asked yet (search summary of the primary pages). — [GoDiS demo paper, 2002](https://preview.aclanthology.org/fix_video/W02-0215.pdf); [Information states and dialogue move engines, 1999](https://dfki.de/etai/SpecialIssues/Dia99/bohlin/isdme_html/node1.html)
- Semantic Machines' dataflow representation (TACL 2020): the dialogue state is a dataflow graph, each user utterance is a program that extends it, and two "metacomputation" operators, refer (reuse an earlier entity or computation) and revise (modify an earlier request), handle reference and correction. The abstract claims these "substantially improve representability and predictability"; no numeric gain is on the abstract page. — [Task-Oriented Dialogue as Dataflow Synthesis](https://arxiv.org/abs/2009.11423)
- Rasa CALM (Bocklisch et al., 2024): an LLM translates the conversation into a small command language (start flow, cancel flow, clarify flows, set slot, correct slot, chitchat, knowledge answer, human handoff), and deterministic business logic executes the commands. The prompt contains the conversation transcript, the latest user message and the collected slots. — [Rasa dialogue understanding](https://rasa.com/docs/rasa-pro/concepts/dialogue-understanding); [Task-Oriented Dialogue with In-Context Learning](https://arxiv.org/abs/2402.12234)

How much context matters, and how many turns
- CSFN-DST (2020) ablation on MultiWOZ 2.1: removing the previous dialogue state from the input lowers joint goal accuracy from 50.81 to 48.66; adding the previous user utterance on top gives 50.75, no gain (search summary). — [CSFN-DST](https://arxiv.org/pdf/2004.03386)
- CHAN (2020): removing the context encoder lowers MultiWOZ 2.1 joint accuracy by 1.72 points (search summary). — [CHAN](https://arxiv.org/pdf/2006.01554)
- STAR (Slot Self-Attentive DST, 2021, full text of Section 6.6): on MultiWOZ 2.1 the full history is best, a model with no history still exceeds 55.5%, and using only 1, 2 or 3 previous turns is slightly worse than using none, which the authors attribute to incomplete history adding confusing information. Exact values are only in a figure. — [STAR](https://ar5iv.labs.arxiv.org/html/2101.09374)
- COMER (2019) authors suspect that carrying only the previous belief state as history hurt their slot prediction (an interpretation, not an ablation; search summary). — [COMER](https://arxiv.org/pdf/1909.00754)

LLM-based tracking
- FnCTOD (Li et al., ACL 2024, full text): zero-shot tracking through function calling, MultiWOZ 2.1, average of per-domain joint goal accuracy: GPT-4 62.59, GPT-3.5 61.31, fine-tuned LLaMA2-13B 59.54, Zephyr-7B 57.68, Baichuan2-13B 56.56, Vicuna-13B 55.41, Vicuna-7B 53.02, LLaMA2-70B-Chat 52.36, LLaMA2-13B-Chat 49.28, LLaMA2-7B-Chat 43.44; earlier small-model zero-shot baselines: D3ST 46.70, T5DST 35.20, TRADE 25.69. The overall (all-domain) joint goal accuracy is far lower: GPT-4 38.71, fine-tuned LLaMA2-13B 37.67. The full dialogue history is given to the model. — [FnCTOD](https://arxiv.org/html/2402.10466v4)
- FnCTOD cost: running the fine-tuned 13B model over the evaluation took about 9.4 to 12.5 hours on one NVIDIA A6000 (workload size not stated). — [FnCTOD](https://arxiv.org/html/2402.10466v4)
- Rasa's own figures for a fine-tuned Llama 3.1 8B command generator: at least 16 GB of GPU memory at 16-bit precision, recommended GPUs A100, L40S or H100, and about 5 requests per second at a median response time below 500 ms. These are vendor figures. — [Rasa: deploying fine-tuned LLMs](https://www.rasa.com/docs/pro/deploy/deploy-fine-tuned-model/); [Rasa: fine-tuning](https://rasa.com/docs/pro/customize/fine-tuning-llm)

### Inferences
- The bot's existing memory (last place, last order, one pending question, one queued order) is already an information state in the TrindiKit sense. What the literature adds is a fixed vocabulary of state edits applied to the last order frame {intent, place, direction}: carry over, replace one slot, delete, repeat, cancel. That vocabulary can be driven by rules; it does not need a tracker model.
- The SOM-DST and CSFN-DST results point the same way for a design with short context: the previous state is worth more than raw previous utterances, and one turn of raw history is the usual amount. STAR shows that a partial raw history can be slightly worse than none, so "a little history" is not automatically safe for a trained model.
- The 53.01 to 81.00 gap is the published measure of what a wrong remembered state costs. For the bot this argues for a state that is cheap to overwrite and that the player can reset with one word, and against a long chain of inherited values.
- Supervised BERT-base trackers at about 27 ms on a GPU are in the same size class as the bot's DeBERTa-v3-base models, so a trained tracker would roughly add one more classifier's cost per utterance on CPU. LLM tracking at 7B and above is outside a CPU budget; this agrees with the project's rejected 1.5B decoder trial (5.4 s per line, from the brief).
- Cross-cutting map of the methods in this note (synthesis of all sections):

| Method | Model needed | Data needed | Published gain from context | Published compute |
|---|---|---|---|---|
| Rule edits over a small frame (carry over, replace slot, repeat, cancel), QUD for fragments | none | none | rule-based carryover: precision 91.79, recall 67.11, F1 77.53 (Alexa internal, 2018) | negligible; no figure published |
| Per-candidate carryover classifier | small LSTM encoder | about 17k labelled sessions (Alexa) | F1 77.53 to 84.16 over rules | no figure published |
| Edit-based utterance rewriter (RUN) | BiLSTM plus small CNN, optional BERT-base | 2.2k to 194k rewrite pairs | exact match 66.4 with BERT on "Rewrite" | 21 ms per sentence, one V100 GPU |
| Seq2seq rewriter (pointer-generator, T5-base, FLAN-T5 80M to 3B) | 128-dimension BiLSTM up to 3B parameters | 16k (ReALM) to 32k (CANARD) | entity F1 at distance 1: 76.6 to 93.7 (CQR) | 55 to 82 ms on a V100 for an LSTM generator; none on CPU |
| History tokens in the encoder classifier | the existing encoder, retrained | multi-turn labelled data | +1.9 to +7 points intent accuracy; -18.8 with the whole history | no figure published |
| LLM command generator or tracker | 7B to 13B | prompts or fine-tuning set | zero-shot average per-domain accuracy 53 to 63 | 16 GB GPU, median under 500 ms (vendor) |
| Recognizer phrase biasing | none (decoding-time) | a phrase list | phrase F-score 42.5 to 70.4 (greedy) or 82.9 (beam) | 2 to 5% slowdown on GPU; beam 11 to 20% slower than greedy |

### Gaps
- No benchmark for multi-turn spoken command and control (games, robots, in-car) with a "with context versus without" comparison was found; MultiWOZ and SGD are information-seeking booking dialogues, far from short imperative orders.
- SGD results, MultiWOZ 2.4 leaderboards and 2025 to 2026 trackers were not collected. A 2025-era "ReacTOD" preprint claiming 52.71% zero-shot joint goal accuracy on MultiWOZ 2.1 with a 20B model and 47.34% with an 8B model appeared only on author listing pages and is unverified.
- MoNET (2022) names a failure mode, "state momentum", in its title ([MoNET](https://arxiv.org/pdf/2211.05503)); its definition and numbers were not captured.
- ConvLab-3, Plato and OpenDial documentation was not examined. Classic rule-based trackers from the DSTC2 era (the "focus" baseline, Wang and Lemon 2013) and Traum's 1994 grounding-acts model are known reference points but were not re-verified in this session.
- Licenses of MultiWOZ and SGD could not be confirmed in this session.
- The Rasa paper's abstract gives no accuracy, cost or latency numbers, and Rasa's latency figures are not independently measured.

## 2. Context carry-over and slot inheritance in voice assistants (Alexa, Apple)

### Takeaway
Alexa moved from hand-written carryover rules to a per-candidate yes/no classifier (2018, F1 77.53 to 84.16), then to joint decisions over all candidate slots (2019), then to rewriting the utterance so the single-turn NLU stays unchanged (2019); Apple moved from a feature-and-rule pipeline (MARRS, 2023) to a fine-tuned FLAN-T5 (ReALM, 2024, 80M to 3B parameters). In Alexa's data 87% of carried slots come from the immediately previous turn and about 1% from three or more turns back.

### Cited Findings
- Naik et al. (Amazon, Interspeech 2018, full text): carryover is a binary decision for each candidate slot taken from the user and system turns in a window of previous turns. Inputs are the current utterance, the context turns, the current intent, the candidate's key and value embeddings, and the candidate's distance in turns (one-hot). Slots from another domain are re-keyed when the key embeddings are similar enough. — [Contextual Slot Carryover for Disparate Schemas](https://ar5iv.labs.arxiv.org/html/1806.01773)
- Results on Alexa's multi-domain set (precision / recall / F1): carry everything 17.01 / 92.50 / 28.74; hand-written rules 91.79 / 67.11 / 77.53; encoder-decoder 73.31 / 96.17 / 83.20; with word attention 75.76 / 94.65 / 84.16. Within one domain the best model scores F1 86.09, across domains 72.19. — [Naik et al. 2018](https://ar5iv.labs.arxiv.org/html/1806.01773)
- Data in that study: 16,905 training sessions, 2.2 turns per session on average, 0.37 positive and 4.07 negative candidate slots per turn, about 20% of sessions with different schemas across turns. — [Naik et al. 2018](https://ar5iv.labs.arxiv.org/html/1806.01773)
- Amazon's own summary: the model beat the rule-based system by about 9% on F1, and the rule system had significantly lower recall. — [Amazon Science blog](https://www.amazon.science/blog/how-alexa-is-learning-to-converse-more-naturally)
- Chen et al. (Amazon, 2019, full text): among carried slots in Alexa's training data about 87% come from distance 1, about 12% from distance 2 and about 1% from distance 3 or more. F1 by distance (1 / 2 / 3 or more): independent baseline 0.8818 / 0.6551 / 0.0000; pointer network with temporal order 0.8631 / 0.6623 / 0.3350; transformer decoder 0.8771 / 0.7035 / 0.3803. Ordering candidates by recency matters: with no order the pointer network falls to 0.8155 / 0.5571 / 0.1290. — [Improving Long Distance Slot Carryover](https://ar5iv.labs.arxiv.org/html/1906.01149)
- Rastogi et al. (Amazon, NAACL 2019 industry track, full text): "contextual query rewriting" serializes the last turns as text, prefixes the predicted domain and intent, replaces entities with role tokens that keep the slot tag and whether the user or the system said them, and rewrites the utterance with a pointer-generator (two-layer BiLSTM, 128 dimensions). Entity F1 by slot distance (0 / 1 / 2 / 3 or more): Naik et al. 95.1 / 76.6 / 76.9 / 17.0; rewriting with role tokens and a copy objective 96.2 / 93.7 / 95.8 / 77.1. — [Scaling Multi-Domain DST via Query Reformulation](https://ar5iv.labs.arxiv.org/html/1903.05164)
- The rewritten utterance goes to the unmodified single-turn understanding component; the paper says the approach "does not require any changes to the agent itself". Downstream task success was not measured, only agreement with gold rewrites. — [Rastogi et al. 2019](https://ar5iv.labs.arxiv.org/html/1903.05164)
- Apple MARRS (Ates et al., 2023, CRAC workshop; abstract only): an on-device framework inside the understanding system that handles conversational, on-screen and background context with two models that complement each other, one for reference resolution and one for query rewriting. — [MARRS](https://arxiv.org/abs/2311.01650)
- Apple ReALM (Moniz et al., 2024, full text): reference resolution as text-to-text with fine-tuned FLAN-T5 in four sizes (80M, 250M, 1B, 3B). Candidate entities are listed as text (type plus properties), the screen is rendered as text, and entities are shuffled so the model does not learn positions. The MARRS baseline, as described here, uses a category module and hand-made text-overlap features. — [ReALM](https://arxiv.org/html/2403.20329v1)
- ReALM accuracy (conversational / synthetic / on-screen / unseen domain): MARRS 92.1 / 99.4 / 83.5 / 84.5; GPT-4 97.0 / 58.7 / 90.1 / 98.4; ReALM-80M 96.7 / 99.5 / 88.9 / 99.3; ReALM-3B 97.9 / 99.8 / 93.0 / 97.8. Training sets are small: 2.3k conversational, 3.9k synthetic and 10.1k on-screen examples. No latency or on-device measurement is reported. — [ReALM](https://arxiv.org/html/2403.20329v1)

### Inferences
- The rule baseline in Naik et al. is the nearest published analogue of the bot's planner: very precise (91.79) and short on recall (67.11). The owner's complaints ("Shoot, shoot, shoot" with a pin placed, "on my pin" after a wrong action) are recall failures of this kind: a value that was available was not inherited.
- The naive "carry everything" row (precision 17.01) is the warning for the opposite mistake: inheriting every remembered value makes most inherited values wrong. Carryover has to be conditional on the slot being needed by the new intent and on recency.
- With 87% of carried slots at distance 1, a memory of one previous order covers most of what published assistants ever carry. The standing pin is different in kind: it is world state the player set on purpose, closer to Apple's "background entity" than to a slot from an old turn, so it can stay valid without a turn limit until the player moves or clears it.
- MARRS scoring 92.1 on conversational references and 99.4 on synthetic ones with rules and overlap features, against 96.7 and 99.5 for the smallest fine-tuned model, suggests that for a closed set of entity types a rule-based resolver gives most of the benefit; the model's clear advantage is on unseen domains (84.5 against 99.3), which the bot does not have.

### Gaps
- No Google Assistant, Siri (beyond MARRS and ReALM) or Cortana paper on slot carryover was retrieved in this session.
- MARRS model types, sizes and accuracy are not in its abstract; the full text was not read.
- No latency figure is published for any of the Alexa carryover models, the pointer-generator rewriter or ReALM.
- The window size D used by Naik et al. and Rastogi et al. is not stated in the text that was read.
- ReALM was read as an arXiv preprint; whether Apple released weights or code was not checked.

## 3. Follow-ups, fragments, corrections and repetition

### Takeaway
The systems that handle fragments and corrections do it with three devices: a question under discussion that turns a bare phrase into a short answer, a slot-edit operation on the previous frame (UPDATE, "correct slot", "revise"), and a detector that the new utterance is a repair of the previous one, which uses the outcome of the previous command and timing as well as the words. Published fragment classifiers reach about 87% weighted F-score over 14 fragment classes; correction detection from prosody alone reached 70 to 75% (1998).

### Cited Findings

Fragments (non-sentential utterances)
- Fernández, Ginzburg and Lappin (Computational Linguistics, 2007; SIGDIAL 2005): classifying non-sentential utterances into a taxonomy of 14 classes with standard machine learning reaches about 87% weighted F-score, a 25% improvement over a simple rule-based baseline; features come from part-of-speech-level information (search summary). — [Computational Linguistics 2007](https://aclanthology.org/J07-3005/); [SIGDIAL 2005](https://aclanthology.org/2005.sigdial-1.9)
- GoDiS / IBiS: an elliptical utterance is treated as a short answer, in Ginzburg's sense, to a question on the QUD, which is why a question must be available to the interpreter (search summary). — [GoDiS demo paper, 2002](https://preview.aclanthology.org/fix_video/W02-0215.pdf)
- Rasa's documentation shows a short reply resolved by the earlier turn: a user who typed "card" and then "cancel" ends up in the cancel-card flow; a fragment such as "to Jen" becomes a set-slot command for the open flow. — [Rasa dialogue understanding](https://rasa.com/docs/rasa-pro/concepts/dialogue-understanding); [Rasa flow policy](https://rasa.com/docs/reference/config/policies/flow-policy)

Corrections and repairs
- Slot-edit model: SOM-DST's UPDATE operation overwrites one slot and leaves the others carried over. — [SOM-DST](https://ar5iv.labs.arxiv.org/html/1911.03906)
- Rasa has a dedicated "correct slot" command ("the user has supplied a new value for a slot that was already set") and a default correction pattern; after a correction "the flow retraces to align with the updated data". The documentation's example asks for confirmation before applying the corrected value. — [Rasa dialogue understanding](https://rasa.com/docs/rasa-pro/concepts/dialogue-understanding); [Rasa conversation repair](https://rasa.com/docs/rasa-pro/concepts/conversation-repair/); [Rasa conversation patterns](https://rasa.com/docs/learn/concepts/conversation-patterns/)
- Dataflow dialogue (2020): a "revise" operator re-runs an earlier request with one part changed, and "refer" retrieves an earlier entity. — [Task-Oriented Dialogue as Dataflow Synthesis](https://arxiv.org/abs/2009.11423)
- SAIF (Azaria and Nivasch, Sensors, 2020): correction detection as a classifier over pairs of consecutive commands, using the audio, the transcripts and whether the agent executed the previous command successfully (search summary). — [SAIF](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC7582502/)
- Levow (1998): spoken corrections show longer utterance and pause duration than the original input; decision trees on duration, pitch and amplitude separate corrections from first attempts with 70 to 75% accuracy (search summary). — [Levow 1998](https://faculty.washington.edu/levow/papers/COLING_ACL_98/coling98.htm)
- Purver, Hough and Howes (Topics in Cognitive Science, 2018): existing other-repair models in dialogue systems cover narrow cases such as system-initiated repair; the authors set incremental processing and robustness to sparse data as requirements and build self-repair and other-repair detectors (search summary). — [Computational Models of Miscommunication Phenomena](https://qmro.qmul.ac.uk/xmlui/handle/123456789/34743)

Repetition after failure
- Bohus and Rudnicky (SIGdial 2005, full text): user turns after a system non-understanding were labelled repeat, rephrase, change, contradict (often a barge-in) or other. "Change" responses were recovered best (63%), and no significant difference was found between the recovery of repeats and rephrases. The paper also restates earlier findings (Swerts et al. 2000; Rotaru and Litman 2005) that after one error the chance of an error in the next turn rises. — [Bohus and Rudnicky 2005](https://aclanthology.org/2005.sigdial-1.14)
- In the same study about 30% of non-understandings came from requests for functions the system lacks, user corrections and out-of-grammar phrasings; the paper blames "a large number" of the non-understandings on recognition errors. — [Bohus and Rudnicky 2005](https://aclanthology.org/2005.sigdial-1.14)
- Alexa's self-learning system (AAAI 2020) treats a user's rephrase after a failed response as an implicit label, learns rewrites from failed to successful phrasings without annotation, and cut the defect rate by more than 30% on utterance-level reformulations in production A/B tests (win/loss ratio 11.8). Amazon's example is a misrecognition: "play alien bridges" mapped to "play leon bridges" (search summary). — [Feedback-Based Self-Learning](https://ar5iv.arxiv.org/html/1911.02557); [Amazon Science blog](https://www.amazon.science/blog/data-efficient-continual-learning-in-alexa)

Grounding
- Clark and Brennan (1991): a contribution is grounded when both parties believe it was understood "to a criterion sufficient for current purposes"; positive evidence of understanding is an acknowledgment, a relevant next turn or continued attention; under "least collaborative effort" a flawed utterance that is easily repaired can be cheaper than a perfect one (secondary summary of the chapter). — [Grounding in communication (summary)](https://en.wikipedia.org/wiki/Grounding_in_communication); [Clark and Brennan 1991, chapter](https://web.stanford.edu/%7Eclark/1990s/Clark,%20H.H.%20_%20Brennan,%20S.E.%20_Grounding%20in%20communication_%201991.pdf)

### Inferences
- "New order or modification of the previous order" is decided in the published systems from four signals, all of which the bot already has or can get without a model: (a) the form of the utterance (a bare place phrase with no action word, or a leading "no", "not", "I said", "again"); (b) whether a question is pending (then a fragment is its answer); (c) whether the previous order had a slot of the type the fragment fills; (d) what happened to the previous order and how long ago (SAIF's "executed successfully" feature, Levow's pause feature).
- Applied to the owner's examples. "No, here, on my pin": NO plus a place fragment is a "correct slot" on the last order's place; the intent is carried over. "On my pin" alone shortly after an order with a place slot: a fragment with no action word is a place replacement on the last order, not a new HOLD_POSITION; outside the window or with no previous order, the current default reading stands. "Shoot again": an explicit repeat marker re-issues the last order of that intent with its slots carried over. "Shoot, shoot, shoot" with a pin placed: an intent that requires a target and names none inherits the most salient standing place (crosshair target if a character is under it, otherwise the pin).
- The current design maps every utterance to one of 41 intents, so a fragment is forced into an order label. The literature treats "this is a fragment or correction" as a category of its own (14 fragment classes; a correction command separate from set-slot). The cheapest equivalent is a rule in front of the planner; the trained equivalent is one or two extra labels (for example PLACE_ONLY and REPEAT) in the classifier, with the planner deciding from the state what they modify.
- The grounding account explains why a silent wrong action is the worst case: the player's only evidence of how the order was understood is what the bot does. A two-word spoken or on-screen echo of the interpreted order ("Firing on your pin") is the bot's side of grounding and gives the player what is needed to issue a one-word correction.

### Gaps
- No published corpus or accuracy figure for corrections and fragments in spoken command and control for games was found.
- The 87% F-score is for classifying the type of a fragment, not for resolving it into a command; the corpus and the per-class scores were not read in this session.
- SAIF's accuracy numbers were not captured, and no source gave a time threshold in seconds that separates a correction from a new command.
- Traum's computational grounding acts (1994) and Ginzburg's full account were not retrieved; incremental (word-by-word) repair processing was only seen through the abstract-level summary of Purver et al.

## 4. Utterance rewriting as a way to give a stateless classifier context

### Takeaway
Rewriting turns "context plus follow-up" into one self-contained utterance so that the existing single-turn classifier is unchanged; Alexa and Apple both shipped or published this design. Edit-based rewriters are about four times faster than generative ones (21 ms against 82 ms on a V100 GPU) but can only use words already present in the dialogue, and no CPU latency is published for any of them.

### Cited Findings
- RUN (Liu et al., Microsoft, EMNLP 2020, full text): predicts a word-level edit matrix between the context and the incomplete utterance with three cell types (none, substitute, insert), using a BiLSTM encoder (GloVe, hidden size 200), similarity features and a U-shaped segmentation network; BERT-base can replace the embedding. — [RUN](https://ar5iv.labs.arxiv.org/html/2009.13166)
- RUN datasets (train / dev / test): Multi 194K / 5K / 5K (Chinese), Rewrite 18K / 2K (Chinese), Task 2.2K / 0.5K (English, task-oriented), CANARD 32K / 4K / 6K (English, question answering). — [RUN](https://ar5iv.labs.arxiv.org/html/2009.13166)
- RUN accuracy: exact match 66.4 with BERT on Rewrite (53.8 without BERT; the pointer baseline T-Ptr-λ scores 52.6, and 57.5 with BERT); exact match 69.2 on Task (GECOR 68.5). — [RUN](https://ar5iv.labs.arxiv.org/html/2009.13166)
- RUN speed, single NVIDIA V100, one sentence at a time: RUN 21 ms; LSTM generator 82 ms with beam 4 and 55 ms with beam 1. — [RUN](https://ar5iv.labs.arxiv.org/html/2009.13166)
- RUN limits: it can only produce words that appear in the dialogue (plus a few connection words), it depends on word order, and each edit cell is predicted independently. The share of examples it can represent exactly is 95.3% (Multi), 91.0% (Rewrite), 87.6% (Task) and 42.5% (CANARD, where annotators introduced many new words). — [RUN](https://ar5iv.labs.arxiv.org/html/2009.13166)
- A later tagging formulation (Chen, 2023) also avoids generation and reports inference faster than most earlier models (search summary). — [Incomplete Utterance Rewriting as Sequential Greedy Tagging](https://ar5iv.org/html/2307.06337)
- Alexa contextual query rewriting (2019): pointer-generator over the serialized context; entity F1 at slot distance 1 rises from 76.6 (per-slot carryover classifier) to 93.7. Reported failure modes: off-topic rewrites when the input has rare words, a rewrite that drops the referent, a rewrite that adds a token that the gold rewrite does not have. — [Rastogi et al. 2019](https://ar5iv.labs.arxiv.org/html/1903.05164)
- Amazon released a public rewrite corpus built on the Stanford in-car dialogues for resolving referring expressions "without explicit need to track the state" (search summary). — [CQR dataset paper, 2019](https://ar5iv.labs.arxiv.org/html/1903.11783)
- T5-base fine-tuned on CANARD scores 58.08 BLEU on the test set against 59.92 for humans (Lin et al., 2020; search summary). A later study finds that BLEU does not compare favourably with other metrics for judging rewrite quality (search summary). — [Lin et al. 2020](https://arxiv.org/pdf/2004.01909); [QReCC paper](https://arxiv.org/pdf/2010.04898)
- Datasets and licenses: QReCC has about 14K conversations and 81K question-answer pairs and is under Creative Commons Attribution-ShareAlike 3.0 Unported. CANARD has 40,527 rewritten QuAC questions and is under CC BY-SA 4.0 (per a dataset index page). — [apple/ml-qrecc](https://github.com/apple/ml-qrecc); [CANARD index page](https://cs.paperswithcode.com/dataset/canard)
- Apple's MARRS pairs a reference resolver with a query-rewrite model on device (abstract). — [MARRS](https://arxiv.org/abs/2311.01650)

### Inferences
- For the bot a rewriter does not have to be a model. The vocabulary is closed and the state is a three-slot frame, so the rewrite is a deterministic template: "shoot again" plus last order {OPEN_FIRE, pin} becomes "shoot at my pin". A rule that writes the canonical sentence, or that skips the sentence and writes the frame directly, has no failure mode of the generative kind (dropped referent, invented token).
- A canonical rewritten sentence is still useful for two things even if the frame is filled by rules: it is the text of the confirmation echo, and it is a way to produce multi-turn training data for a contextual classifier from single-turn data.
- If a trained rewriter is ever wanted, the edit-based family fits better than the generative one: its restriction to words in the dialogue is not a restriction for a closed command vocabulary, and its failure cases are bounded. Its published 21 ms is on a GPU; on the minimum CPU it would be an additional encoder pass of unknown cost.
- CANARD and QReCC are question-answering data under share-alike licenses; they are neither the right domain nor a comfortable license for a commercial product. Rewrite data for commands would have to be generated in the project.

### Gaps
- No CPU latency is published for RUN, the tagging rewriter, the pointer-generator or T5-class rewriters.
- No rewriting result on spoken commands with recognition errors in the input was found; all figures are on clean text.
- The license of Amazon's public CQR corpus was not checked.
- RUN's code license was not checked.

## 5. Feeding history directly to the encoder classifier

### Takeaway
In the published task-bot studies, adding the immediately previous turn or the previous intent to the classifier input gains between about 2 and 7 points of intent accuracy on mixed data and far more on follow-up-heavy data, while adding the whole history can lose 19 points. The one ablation that separates the signals finds the history of previous intents to be the most valuable single signal.

### Cited Findings
- CASA-NLU (Gupta et al., Amazon AI, 2019, full text): context signals are previous intents, previous dialogue acts, slot history and previous utterances over a window of K = 3 turns, chosen from a search over 1 to 5. — [CASA-NLU](https://ar5iv.labs.arxiv.org/html/1909.08705)
- CASA-NLU intent accuracy without and with context: Booking 91.11 to 95.16; Cable 44.98 to 73.94 (a GRU context encoder reaches 94.86 and 66.68). Slot F1: Booking 88.21 to 88.80; Cable 27.34 to 56.97. — [CASA-NLU](https://ar5iv.labs.arxiv.org/html/1909.08705)
- CASA-NLU ablation, intent accuracy on the Booking validation set: no context 89.44; plus utterance history 92.52; slot, utterance and dialogue-act history without intent history 92.35; intent, slot and utterance history without dialogue acts 95.27; all signals 96.53. Intent history gives the largest gain; the authors say the best signals depend on the dataset. — [CASA-NLU](https://ar5iv.labs.arxiv.org/html/1909.08705)
- CASA-NLU accuracy on first turns and follow-up turns: Booking 99.70 and 94.45; Cable 47.44 and 81.25. The paper does not test noisy or wrong context. — [CASA-NLU](https://ar5iv.labs.arxiv.org/html/1909.08705)
- Farfan-Escobedo and Dos Reis (2024, full text): multilingual BERT plus a CNN, 22 intents, 36,056 user queries in 7,574 conversations (Brazilian Portuguese). Accuracy: no context 85.32; the previous user utterance only 87.18 (+1.86); the previous system response only 86.56 (+1.24); previous user and system 86.08 (+0.76); several previous user messages 78.00 (-7.32); the whole history 66.52 (-18.80). With a modified loss the best is again the last user utterance, 87.58 against 85.19. — [Improved intent classification with a windows-based approach](https://arxiv.org/html/2411.06022v1)
- An Amazon patent (US 11568145) describes feeding the previous intent, the previous dialogue act and the slot being elicited together with the user utterance into a BERT-based understanding model; no accuracy is given (search summary). — [US 11568145](https://patents.justia.com/patent/11568145)
- Skit.ai reports intent F1 0.890 with a memory-network context encoder against 0.865 when only the last system prompt is encoded (company blog; search summary). — [Skit.ai contextual SLU](https://tech.skit.ai/contextual-slu/)
- From tracking: the previous state is worth 2.15 points of joint goal accuracy in CSFN-DST, an extra previous user utterance nothing (search summary); a wrong previous state costs SOM-DST the difference between 81.00 and 53.01. — [CSFN-DST](https://arxiv.org/pdf/2004.03386); [SOM-DST](https://ar5iv.labs.arxiv.org/html/1911.03906)

### Inferences
- The consistent pattern is "structured and recent beats raw and long": previous intent and previous state help; one previous utterance helps a little; many previous utterances hurt. For the bot the natural input is the current utterance plus a few state tokens, for example the last order's intent, whether a question is pending and which, whether a pin exists, and whether the last order was carried out, not the transcript of earlier lines.
- The size of the gain depends on how many follow-up-dependent lines the data has. On the Booking set and the 22-intent Portuguese set it is 2 to 5 points; on the Cable set, where the model without context is at 44.98%, it is 29 points. The bot's benefit would be concentrated in the fragment, correction and repeat lines and close to zero on full orders, so it should be measured on a follow-up test set, not on the overall accuracy.
- Risks that the cited work supports: over-reliance on context (the whole-history rows at -7 and -19 points; STAR's slightly worse partial history) and propagation of an earlier error (SOM-DST). A trained contextual classifier that was fed a wrong "last intent" has no published robustness result; the usual mitigations (dropping the context tokens at random during training, training with corrupted context) are engineering practice and were not verified against a source here.
- Data cost: there is no public multi-turn spoken command corpus, so the multi-turn training data would have to be synthesized from the single-turn data and the planner's rules. In that case the classifier learns the rules it was generated from; the trained route then adds robustness to wording, not new knowledge, and the rule route gives the same behaviour with no retraining of three DeBERTa models.
- Compute: state tokens add a few tokens to a short input, so the added latency should be small next to the 40 to 70 ms the ensemble already takes; no measurement is published for this.

### Gaps
- No study with DeBERTa specifically, and none on imperative spoken commands, was found.
- No published measurement of what a wrong context token does to a contextual intent classifier was found.
- CASA-NLU's two datasets are internal to Amazon; its paper is inconsistent about the number of intents and slots in the Cable set.
- The end-to-end spoken-understanding paper on dialogue history ([Ganhotra et al. 2021](https://arxiv.org/pdf/2108.08405)) was seen only in a search summary without a context-gain figure.

## 6. Clarification and confirmation: when to ask and when to act

### Takeaway
The evidence from spoken dialogue systems is against "say again" as the default response to uncertainty: asking the user to repeat recovered 33.7% of non-understandings, while moving the task forward with a different plan recovered 64.4% and short "you can say" help 56.5%. Published guidance reserves explicit confirmation for actions that are hard to undo, and the embodied-agent results show that asking only when the candidate set is ambiguous matches asking always at a fraction of the questions.

### Cited Findings
- Bohus and Rudnicky (SIGdial 2005, full text): ten recovery strategies were compared in a conference-room reservation system (46 participants, 449 sessions, 8,278 user turns). Recovery rates: MoveOn 64.4%, FullHelp 58.5%, TerseYouCanSay 56.5%, Reprompt 49.2%, YouCanSay 48.6%, AskRephrase 48.6%, DetailedReprompt 37.7%, Notify 35.7%, AskRepeat 33.7%, Yield 31.2%. The top three do not differ significantly from each other; the last four do not differ from each other. — [Bohus and Rudnicky 2005](https://aclanthology.org/2005.sigdial-1.14)
- In the same study MoveOn means the system ignores the non-understanding and advances the task with a different question; the recovery rate has the greatest effect on task success while it is below 60 to 70%; a human wizard choosing the strategy reached 50.1% against 46.5% for an uninformed policy, and 69.8% on the cases where the wizard's choice matched the best-recovery policy. — [Bohus and Rudnicky 2005](https://aclanthology.org/2005.sigdial-1.14)
- Skantze (2003): human operators who saw only the recognizer's output mostly did not signal non-understanding; they asked task-related questions to confirm their hypothesis about the situation. That led to better understanding of the following utterances, while signalling non-understanding lowered the users' sense of task success; users reported that they were almost always understood despite many non-understandings (search summary; a small wizard study). — [Skantze 2003](https://www.cs.columbia.edu/~julia/papers/skantz03.pdf); [Skantze thesis, chapter 4](https://www.speech.kth.se/~gabriel/thesis/chapter4.pdf)
- Google's conversation design guidance: explicit confirmation of actions is rare and is for actions that would be difficult to undo; implicit confirmation (restating the understood parameters) is used most of the time; no confirmation is needed when the action itself makes the understanding obvious, as with "stop" or "cancel", or when the input is simple and recognized with high confidence, as with yes/no. Implicit confirmation lets users correct mistakes immediately (search summary of the official page). — [Google conversation design: confirmations](https://developers.google.com/assistant/conversation-design/confirmations?hl=en)
- KnowNo (Ren et al., CoRL 2023): the planner's scored options are turned into a prediction set by conformal prediction; if the set has more than one option the robot asks for help. This reaches a user-chosen task success level while reducing human help by 10 to 24% (preprint) or 10 to 15% (proceedings version) against baselines. The two versions give different ranges (search summary). — [KnowNo preprint](https://arxiv.org/pdf/2307.01928); [KnowNo, CoRL proceedings](https://proceedings.mlr.press/v229/ren23a.html)
- DialFRED (Gao et al., 2022, full text): in embodied instruction following, success on unseen scenes is 18.3% with the instruction only, 32.0% when every available question is asked (3.24 questions on average), 33.6% with a learned policy that asks 0.71 questions on average, and 33.0% when asking only when the model is confused (0.31 questions). Asking at every step gives 34.7% at 21.39 questions. — [DialFRED](https://ar5iv.labs.arxiv.org/html/2202.13330)
- Rasa's default example for a correction asks before applying it ("Should I update your name to Jonathan in my records?"). — [Rasa conversation repair](https://rasa.com/docs/rasa-pro/concepts/conversation-repair/)
- Clark and Brennan's least collaborative effort: an easily repaired flawed contribution can cost the pair less than a perfect one. — [Grounding in communication (summary)](https://en.wikipedia.org/wiki/Grounding_in_communication)

### Inferences
- A default-with-undo policy is what these sources support for orders that are cheap to reverse (move, hold, follow, cover): act on the best reading, say in two or three words what was understood, and treat the next utterance as a possible one-word correction. Asking is for the two cases the sources single out: the action is hard to undo (a grenade, opening fire when hold-fire was standing, leaving cover under fire), or the candidate set has more than one member of similar score (two markers called "door", "there" with nothing under the crosshair and no pin).
- "Say again" is the bot's AskRepeat, the second-worst strategy in the 2005 comparison. The better-performing alternatives translate to: (a) act on the reading that the state makes most likely and announce it (MoveOn); (b) ask a question about the task, not about the words ("Fire on your pin?" answered by YES or NO, which the classifier already has); (c) a terse hint of what can be said. A targeted yes/no question also brings the next utterance into the regime where recognition is most reliable.
- KnowNo's rule is directly usable without a language model: build the set of readings whose score is within a margin of the best, using classifier probabilities and the number of groundable places, and ask only if more than one reading survives. The threshold can be calibrated on held-out lines to a chosen error rate, which is what conformal prediction does.
- DialFRED's result that asking when confused (0.31 questions) performs like asking always (3.24 questions) is the quantitative argument for selective asking; it is from a slow household-task simulator, so only the direction carries over to a shooter.

### Gaps
- No controlled comparison of "act and allow undo" against "ask first" with task time and preference measures was found for voice command of game companions or robots; the HRI search returned only adjacent work.
- No published user study on spoken companions in games was retrieved in this session.
- The 2005 strategy comparison is from a telephone-style booking system with year-2005 recognition; the ranking is likely more durable than the percentages.
- Skantze's and Google's material was seen through summaries; exact wording should be re-read before quotation.

## 7. Time and salience: how context is decayed

### Takeaway
Published windows are short: consumer assistants keep listening for a follow-up for about 5 seconds (Alexa) or 8 seconds (Google), understanding models use one to three previous turns, and 87% of carried slots in Alexa's data come from the previous turn. Recency is used as an explicit feature (distance in turns, recency ordering of candidates); no source gives a decay in seconds for carried slots, and no deployed use of centering theory was found.

### Cited Findings
- Alexa's Follow-Up Mode listens for about five seconds after a response; Google Assistant's Continued Conversation listens for an additional eight seconds after each query (press coverage from 2018 to 2019; current values not confirmed). — [TechRadar](https://www.techradar.com/how-to/what-is-alexa-conversation-mode-and-how-does-it-work); [VentureBeat, 2019](https://venturebeat.com/2019/03/08/google-brings-continued-conversation-to-google-assistant-smart-displays); [TechHive](https://www.techhive.com/article/578300/how-to-set-alexa-and-google-assistant-to-listen-for-follow-up-questions.html)
- Distance of carried slots in Alexa's data: about 87% one turn back, 12% two turns back, 1% three or more. — [Chen et al. 2019](https://ar5iv.labs.arxiv.org/html/1906.01149)
- Recency as a feature: Naik et al. encode the candidate slot's distance in turns as a one-hot input and note that their naive baseline rests on the assumption that recent entities are the ones users refer back to; Chen et al. find that ordering candidates by distance from the current turn significantly beats no ordering (F1 at distance 2: 0.6623 against 0.5571). — [Naik et al. 2018](https://ar5iv.labs.arxiv.org/html/1806.01773); [Chen et al. 2019](https://ar5iv.labs.arxiv.org/html/1906.01149)
- Window sizes chosen in understanding models: CASA-NLU picks K = 3 from 1 to 5; SOM-DST uses one previous turn plus the previous state; the best configuration in the 2024 window study is the single previous user utterance. — [CASA-NLU](https://ar5iv.labs.arxiv.org/html/1909.08705); [SOM-DST](https://ar5iv.labs.arxiv.org/html/1911.03906); [Farfan-Escobedo and Dos Reis 2024](https://arxiv.org/html/2411.06022v1)
- Alexa sessions in the carryover study average 2.2 turns. — [Naik et al. 2018](https://ar5iv.labs.arxiv.org/html/1806.01773)
- Apple's ReALM treats three kinds of candidate entity together: on-screen, conversational and background (for example a ringing alarm or playing music). — [ReALM](https://arxiv.org/html/2403.20329v1)
- Situated reference in human-robot dialogue (search summaries): Schütte, Kelleher and Mac Namee resolve exophoric references in the SCARE corpus by the visual salience of candidate referents and report that this lightweight approach works; Gross, Krenn and Scheutz (2017) find that only up to 50% of references to objects can be resolved even with language, eye gaze and pointing combined; Gieselmann reports that most pronouns in household-robot dialogue can be resolved by a simplified pragmatic approach based on focus and salience. — [Schütte et al.](https://arrow.dit.ie/scschcomcon/67); [Gross et al. 2017](https://hrilab.tufts.edu/publications/grossetal17icmi); [Gieselmann](https://isl.iar.kit.edu/english/5265.php)
- A 2025 system that combines gaze and speech with an LLM uses "Can you put this there?" as its example of an underspecified reference that needs a non-verbal signal. — [SemanticScanpath](https://arxiv.org/html/2503.16548v1)

### Inferences
- Two different kinds of context should decay differently. Discourse context (the last order, the last place said, a pending question) is turn-based and short: the published numbers support keeping one previous order, and a follow-up window of the same order as the assistants' 5 to 8 seconds is a defensible starting value for "a bare fragment modifies the last order". Situational context (the pin, the crosshair target, the bot's stance) is not discourse memory at all: it is valid for as long as the world says it is, and should be invalidated by events (pin moved or removed, target dead, order completed), not by a clock.
- A fast shooter probably needs event-based expiry more than a time constant: an order that has been completed or cancelled should stop being the antecedent for "again" or "no, here" sooner than an order still in progress, and a correction arriving while the bot is still carrying out the order is the strongest case for "modify" over "new order". This follows from SAIF's use of the previous command's outcome, not from a published window.
- A fixed salience ranking is the practical form of centering for this setting: explicit place in the utterance, then the pointed spot for "here", "there", "this", "that", then the standing pin, then the last place used. The "up to 50%" result for gaze and pointing in human-robot dialogue does not transfer directly, because in the game the crosshair point is exact and is sent with every utterance; deictic words can therefore be grounded far more reliably than in the robot studies.
- "Here" and "there" may need the proximal/distal distinction only as a tie-breaker: with one pointed spot available both words mean that spot; the distinction matters when both the player's own position and a pointed spot are candidates.

### Gaps
- No source states a time-based decay or expiry in seconds for carried slots in Alexa, Google Assistant or Siri; the 5 and 8 second figures are microphone-reopening windows, not context lifetimes.
- No in-car or robot command system with a documented context window was retrieved.
- No evidence of centering theory used as such in a deployed command system was found; the salience-ranking practice above is supported only by the summaries of the robot-dialogue papers.
- The window D in the Alexa carryover and rewriting papers is not given in the text that was read.

## 8. Robustness to recognition errors with context

### Takeaway
The retraining-free tool is phrase-list biasing at decoding time; it is published to raise the F-score on listed phrases from 42.5 to 70.4 with greedy decoding and to 82.9 with beam search for a transducer, at a few points of precision. sherpa-onnx implements it for transducers under modified beam search only, and its current source carries a NeMo TDT path with a context graph, though the official hotwords page does not mention NeMo models. Dialogue-context rescoring of the recognizer's alternatives is reported to cut word error rate by about 2 to 9% relative.

### Cited Findings

sherpa-onnx hotwords
- The official hotwords page (full text): only transducer models (offline and streaming) support hotwords, "All other models don't support hotwords"; the decoding method must be modified_beam_search, greedy_search does not support hotwords; no retraining is needed. — [sherpa-onnx hotwords](https://k2-fsa.github.io/sherpa/onnx/hotwords/index.html)
- Mechanism and format: hotwords are tokenized and compiled into an Aho-Corasick automaton; the boost is applied on partial matches and cancelled if the phrase is not completed. The file has one phrase per line with an optional per-phrase score suffix such as " :3.5"; the global hotwords-score appears as 1.5 in the configuration dumps; BPE models need a bpe.vocab file and the modeling unit must match the model. — [sherpa-onnx hotwords](https://k2-fsa.github.io/sherpa/onnx/hotwords/index.html)
- The page reports no accuracy metric, only before/after examples. Its real-time factors with and without hotwords are close (offline C++ with two threads 0.076 without and 0.065 with; Python with one thread 0.109 and 0.106); the hardware is not stated. — [sherpa-onnx hotwords](https://k2-fsa.github.io/sherpa/onnx/hotwords/index.html)
- Source code on the master branch, read on 2026-10-10: the NeMo transducer recognizer accepts greedy_search and modified_beam_search and exits with "Unsupported decoding method" otherwise; the hotwords file is loaded only in the modified_beam_search branch; there is a CreateStream overload that takes a hotwords string and builds a context graph for that stream. — [offline-recognizer-transducer-nemo-impl.h](https://raw.githubusercontent.com/k2-fsa/sherpa-onnx/master/sherpa-onnx/csrc/offline-recognizer-transducer-nemo-impl.h)
- The NeMo modified-beam-search decoder on master handles TDT models (it splits the joiner output into token and duration logits, picks the duration by argmax, and advances by the predicted number of frames) and applies the context graph (a hotwords score added to matching tokens, ForwardOneStep on non-blank tokens, Finalize at the end). The automated reading of this file flagged that the bonus might be counted twice; this was not confirmed. — [offline-transducer-modified-beam-search-nemo-decoder.cc](https://raw.githubusercontent.com/k2-fsa/sherpa-onnx/master/sherpa-onnx/csrc/offline-transducer-modified-beam-search-nemo-decoder.cc)
- A third-party wrapper's documentation states that hotwords work for the "transducer" and "nemo_transducer" model types only and that it switches to modified_beam_search automatically when a hotwords file is given. The sherpa-onnx changelog lists "Support TDT transducer decoding (#2495)" and "Fix TDT decoding for NeMo TDT transducers (#2606)" (search summary). — [react-native-sherpa-onnx hotwords guide](https://www.mintlify.com/xdcobra/react-native-sherpa-onnx/guides/hotwords); [sherpa-onnx changelog](https://pub.dev/packages/sherpa_onnx_linux/changelog)

Phrase boosting for NeMo and Parakeet
- NVIDIA's documentation lists GPU-PB phrase boosting for CTC, RNN-T/TDT and Canary models, in greedy and beam decoding, applied only at decoding time; for models that capitalize by default, such as parakeet-tdt-0.6b-v2, the key phrases must be capitalized in advance. A model-page discussion says word boosting for TDT arrived in NeMo 2.5.0 (search summary). — [NeMo word boosting](https://docs.nvidia.com/nemo/speech/latest/asr/asr_customization/word_boosting.html); [parakeet-tdt-0.6b-v3 discussion](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3/discussions/3)
- TurboBias (Andrusenko et al., NVIDIA, 2025, full text) evaluates a 114M-parameter FastConformer hybrid transducer-CTC model and Canary (179M); Parakeet TDT is not among the tested models. RNN-T on the CSTalks set (200 phrases), F-score on listed phrases (precision / recall) and word error rate: greedy 42.5 (96/27) and 12.8% without boosting, 70.4 (92/57) and 10.7% with; beam 44.2 (97/29) and 12.8% without, 82.9 (90/76) and 9.6% with. On Earnings21 (893 phrases) greedy goes from 56.0 to 63.3 with the word error rate nearly unchanged (15.1% to 15.0%). — [TurboBias](https://arxiv.org/html/2508.07014v2)
- TurboBias cost and false accepts: 2 to 5% slowdown, beam search 11 to 20% slower than greedy, measured on one RTX A6000 at batch size 32. With the list grown to 20,000 phrases the boosting weight had to be lowered from 1 to 0.7 "to avoid a large number of false accepts", giving F-score 78.4% and word error rate 11.42% against 44.2% and 12.83% without boosting. The paper describes icefall's phrase boosting as CPU-only. — [TurboBias](https://arxiv.org/html/2508.07014v2)
- Misrecognition variants as extra entries: Liu et al. (2025) synthesize each rare word with text-to-speech, transcribe the audio to collect the recognizer's spelling variants, put the variants in the trie and map any recognized variant back to the intended word; biased-word error rate falls 43% and 44% on LibriSpeech test-clean and test-other with the unbiased rate essentially unchanged (Whisper; abstract). — [Zero-shot context biasing with synthetic multi-pronunciation](https://arxiv.org/abs/2508.17796)
- Huber and Waibel (August 2026, abstract): two Whisper-based biasing methods cut the word error rate on listed words by up to 88% relative while leaving other words largely unaffected; speech LLMs given the list in the prompt do well on read speech, generalize less well to non-read speech, and are sensitive to the number of distractor words and their order. — [How to Recognize New Words](https://arxiv.org/abs/2608.05759)

Dialogue context in recognition and rescoring
- Shenoy, Bodapati and Kirchhoff (2021): a neural language-model rescorer that uses the system's dialogue acts, the system prompt and context carried across turns gives a 7% relative word error rate reduction over a non-contextual LSTM baseline on in-domain data (search summary). — [Contextual biasing of language models in goal-oriented agents](https://arxiv.org/pdf/2103.10325)
- Long-context language models for rescoring in task-oriented agents (2021): relative word error rate reductions between 1.6% and 9.1% and a slot-labelling F1 gain of 4% over non-contextual baselines (search summary). — [Adapting long context NLM for ASR rescoring](https://arxiv.org/pdf/2104.11070)
- Joint contextual modelling of recognition correction and understanding on DSTC2 (2020): errors of an off-the-shelf recognizer and the understanding that follows are reduced by 14% relative with small amounts of in-domain data (search summary). — [Joint contextual modeling for ASR correction and LU](https://arxiv.org/abs/2002.00750)
- BERT rescoring of n-best lists with previous utterances (2021): word error rate recoveries of up to 37.2% in low-resource settings; the best context length depends on the domain, shorter for customer-service calls (search summary). — [Context-augmented BERT rescoring](https://arxiv.org/pdf/2110.02267v1)
- Apple's transformer rescorer over the whole n-best list reports up to 8.6% average relative word error rate reduction; it is not a dialogue-history method (search summary). — [Apple: ASR n-best rescoring and rewriting](https://machinelearning.apple.com/research/asr-n-best-rescoring)
- Recovery from misrecognition after the fact: Alexa's rewrite system learned from user rephrases corrects recognition errors such as "alien bridges" for "leon bridges" (search summary). — [Amazon Science blog](https://www.amazon.science/blog/data-efficient-continual-learning-in-alexa)
- Google's guidance treats yes/no answers as inputs "typically recognized with high confidence" (search summary). — [Google conversation design: confirmations](https://developers.google.com/assistant/conversation-design/confirmations?hl=en)

### Inferences
- The bot's command vocabulary is closed and small (a few hundred words at most), which is the favourable end of the published range: the gains above are for 200 to 1,000 phrases, and false accepts became a problem only at 20,000. A phrase list of the action words and place words is therefore the first thing to try against errors such as "Shoot there" heard as "Should there".
- Biasing in sherpa-onnx requires leaving greedy search for modified beam search. That costs latency on top of the present 150 to 250 ms; the only published overhead figure (11 to 20%) is for NeMo's own decoder on a GPU, so the cost for Parakeet TDT 0.6B on the minimum CPU has to be measured. The NeMo TDT hotword path exists in the source but is absent from the official hotwords page, so its behaviour should be verified with a word-error and false-accept test before it is relied on, including the possible double counting noted above.
- Two context-aware tricks need no model. First, the per-stream hotword string in sherpa-onnx's NeMo recognizer allows the phrase list to change with the state: after a yes/no question, boost the answer words; when a pin exists, boost "pin". This is the cheap version of the dialogue-act-conditioned rescoring in the cited papers. Second, the confusion-variant idea from Liu et al. can be applied after recognition instead of inside it: a small alias table from known misrecognitions to the intended command ("should there" to "shoot there"), built by running the recognizer over synthesized or recorded commands. Alexa's rephrase-learned rewrites are the data-driven form of the same table.
- The classifier is itself a form of error correction if it has seen the misrecognized forms: adding the recognizer's actual outputs for each command to the training data (noise-aware training) uses the existing pipeline and no new component. This is a practice, not a result cited here.
- Context can also arbitrate between readings after classification: if the top two intents are close and only one of them is executable in the current state (it has a groundable place, or it answers the pending question), the planner can prefer that one. This is the same expected-answer idea moved from the recognizer to the planner.

### Gaps
- No published accuracy figure exists for sherpa-onnx hotwords with Parakeet TDT, and none for any transducer in sherpa-onnx (the documentation gives examples only). icefall's own context-biasing result tables were not found in this session.
- No CPU latency figure for modified beam search with hotwords on a 0.6B TDT model was found.
- Whether sherpa-onnx exposes n-best alternatives for NeMo transducers, which rescoring with dialogue context would need, was not checked.
- TurboBias did not test Parakeet TDT, and its timings are for a GPU.
- No study of recognizer biasing or contextual rescoring on short game commands spoken under time pressure was found.
