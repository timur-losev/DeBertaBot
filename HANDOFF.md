# Снимок проекта: ко-оп бот на DeBERTa-v3 (для продолжения на макбуке)

Снимок сделан 2026-10-03 с рабочей машины (Windows, RTX 4090). Здесь описано, что лежит в архивах,
как запустить бота на Mac, в каком состоянии работа и что делать дальше.

## 1. Что в архивах

| архив | что внутри | размер |
|---|---|---|
| `coop-bot-code.tar.gz` | `project_synth/`: документы, `scripts/coop/` (данные, обучение, оценка, логи, результаты), `cpp/coop_intent/` (C++-движок без сборки и без ONNX Runtime) | ~50 МБ |
| `coop-bot-models.tar` | `project_synth/models/coop-deberta-v3-ens3-v2/` (боевой бот v2: три модели + экспорт для C++) и `coop-deberta-v3-base/` (прошлый бот v1) | ~5,6 ГБ |

Оба архива распаковываются в одну папку, скрипты ищут друг друга по относительным путям:

```
mkdir ~/coop && cd ~/coop
tar -xzf coop-bot-code.tar.gz
tar -xf  coop-bot-models.tar
cd project_synth
```

В архивах нет:
- экспериментов с laya, Qwen и ollaya (`models/coop-laya-ft`, остальные папки `scripts/`);
- Windows-сборки ONNX Runtime и папки `build/`.

## 2. Python-бот на Mac

```
python3.11 -m venv .venv && source .venv/bin/activate
pip install torch "transformers==5.17.0" "tokenizers==0.23.2" onnxruntime onnx scikit-learn numpy
cd scripts/coop
python coop_bot.py            # текущий бот v3 (24 приказа, ансамбль из трёх моделей, места), на CPU
python coop_bot.py --model ../../models/coop-deberta-v3-ens3-v2     # бот v2, если архива с v3 нет
```

- Версии `transformers` и `tokenizers` — те, на которых всё обучалось и проверялось. С другими
  токенизатор может дать другие id.
- На рабочей машине использовались два окружения:
  - `jev` (torch + transformers) — для обучения и бота;
  - базовая anaconda (scikit-learn) — для `eval_v2.py` и `eval_v3.py`.

  На Mac хватит одного окружения с пакетами из команды выше.
- Команды в чате: `/why`, `/t 0.6`, `/q`. Под ответом бот печатает места, которые нашёл в реплике
  (строка `place:`).

## 3. C++-движок на Mac

**На macOS сборка не проверялась.** `CMakeLists.txt` и код подготовлены под macOS и Linux, но собирались
только на Windows (MSVC).

```
cd cpp/coop_intent/third_party
curl -LO https://github.com/microsoft/onnxruntime/releases/download/v1.30.0/onnxruntime-osx-arm64-1.30.0.tgz
tar -xzf onnxruntime-osx-arm64-1.30.0.tgz
xattr -dr com.apple.quarantine onnxruntime-osx-arm64-1.30.0     # если macOS блокирует библиотеку
cd ..
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/coop_cli --threads 1          # чат
```

Проверки паритета с Python-ботом. Эталонные файлы лежат в `models/coop-deberta-v3-ens3-v3/cpp/` (бот по умолчанию). Без архива с v3
добавь к командам `--model-dir ../../models/coop-deberta-v3-ens3-v2/cpp`:

```
./build/coop_cli --tokenizer-tests     # токенизатор и регэкспы, без модели
./build/coop_cli --location-tests      # места в реплике, без модели
./build/coop_cli --gate-tests
./build/coop_cli --decide-tests
./build/coop_cli --golden              # с моделью: вероятности против PyTorch
./build/coop_cli --dialogue
```

- На Intel-Mac нужен пакет `onnxruntime-osx-x86_64-1.30.0.tgz`.
- Если какая-то проверка не сойдётся на Mac, это ошибка переносимости. Её стоит разобрать до переноса
  в UE.

## 4. Состояние работы

**Сделано и проверено: бот v2**
- 24 приказа, включая TAKE_COVER и OPEN.
- Ансамбль из трёх DeBERTa-v3-base, гейт по семейству, порог 0.58. Модель лежит в
  `models/coop-deberta-v3-ens3-v2`.
- Кросс-валидация по авторам: попадание 90.5%, действия из чужого семейства 1.9%.
- C++ совпадает с Python на всех проверках.
- Подробности: `COOP-BOT.md` (раздел «v2») и `DEBERTA-BOT.md` (раздел 11).

**В работе: v3, места на карте (коллауты)**

Идея: названия мест не учит модель. Их находит словарь с правилами и отдаёт планировщику цель.

- `scripts/coop/locations.json` — словарь: двери и окна по сторонам света, Main door, лестницы по
  цветам, мебель, этажи; синонимы; списки слов для правил. Новый коллаут — строка в этом файле.
- `scripts/coop/locations.py` — сопоставитель. Отдаёт все места строки по порядку с ролями (моё место,
  место врага, «откуда», «не это») и пометами, плюс основную цель. Регрессионный набор разработчика:
  `python locations.py --dev`.
- C++-порт: `cpp/coop_intent/src/locations.cpp`. Совпадает с Python на 8570 из 8570 строк.
- Бот (Python и C++) отдаёт места с каждой репликой. Отложенный приказ («on my go») хранит своё место и
  выполняется по нему.
- Слепые данные v3: `blind/v3`, `annot/v3` — 3 автора по 50 строк, по 2 аннотатора на автора.

Результаты на 150 слепых строках (`eval_v3.log`; первый прогон до правки правил —
`eval_v3_rules_v1.log`):

| что | результат |
|---|---|
| сопоставитель, правила v1 (до просмотра строк) | точная цель на 88.0% |
| сопоставитель, правила v2 (правлены по авторам r6 и cs) | 94% на отложенном авторе stt; 96.7% на всех |
| боевая модель v2 на строках с местами, сырая строка | попадание 83.3%, чужое семейство 3.3% |
| то же, названия вырезаны перед классификатором | хуже на 3.3 пункта |

- Вывод: модель читает сырую строку.
- Известная ошибка модели v2: «get up on the roof» → RAPPEL. Её должно починить дообучение.

**Кросс-валидация v3 досчитана** (дообучение на строках с местами и seed-командах с местами,
`seed_commands_v3.json`; результаты в `results_v3_probs_{r6,cs,stt}.json`, раздел C в `eval_v3.log`):

| | попадание на строках с местами | чужое семейство |
|---|---|---|
| боевой бот v2 | 83.3 | 3.3% |
| дообученный ансамбль (гейт top / family) | 90.0 / 90.7 | 1.3% |

- Разница на строках с местами: +10.7 [+3.3, +18.7] для top и +11.3 [+4.0, +19.3] для family.
- На 483 старых строках разница 0.0 / −0.2 [−4, +4], то есть старые приказы не пострадали.
- Вывод: дообучение нужно, финальная модель v3 — следующий шаг.

**Финальная модель v3 обучена, экспортирована и проверена** (после первого снимка; в архив
`coop-bot-models.tar` она не вошла и лежит в отдельном архиве `coop-bot-model-v3.tar`):
- `models/coop-deberta-v3-ens3-v3`: гейт по семейству, порог 0.52;
- все шесть проверок `coop_cli` проходят на Windows;
- бот по умолчанию (`coop_bot.py`, `CMakeLists.txt`) переключён на v3.

## 5. Что делать дальше

1. На Mac: собрать C++ и прогнать шесть проверок (раздел 3). Это первая сборка вне Windows.
2. Этап 2 — плагин UE5. План в `cpp/coop_intent/README.md`:
   - модель через NNE;
   - регэкспы через ICU по ASCII-«тени»;
   - места — теги на акторах уровня, `Decision::places` передаётся планировщику как есть.
3. После первых игровых сессий:
   - разметить реальные реплики из лога и добавить в обучение;
   - собрать варианты названий мест от настоящего распознавания речи («rough», «stares») и добавить в
     `locations.json`.
4. Если понадобится переобучить (нужен GPU; на Mac без него — часы, в `train_v2.py` только `cuda` или
   `cpu`):
   ```
   COOP_TAG=v3 python scripts/coop/train_v2.py final ens3      # -> models/coop-deberta-v3-ens3-v3
   COOP_TAG=v3 python scripts/coop/export_cpp.py models/coop-deberta-v3-ens3-v3
   COOP_TAG=v3 python scripts/coop/check_onnx.py  models/coop-deberta-v3-ens3-v3
   COOP_TAG=v3 python cpp/coop_intent/tools/gen_tests.py models/coop-deberta-v3-ens3-v3
   ```

Если поменялся только словарь мест или регэкспы, переобучать не нужно:

```
python scripts/coop/locations.py --dev
python scripts/coop/export_cpp.py models/<бот> --config-only
python cpp/coop_intent/tools/gen_tests.py models/<бот>
```

## 6. Правила, которых держится проект

- **Заморозка.**
  - Спецификация, seed-команды и правила фиксируются до появления тестовых строк. Хэши и порядок
    записаны в `scripts/coop/frozen.txt`.
  - Если что-то правится после просмотра тестовых строк, это записывается там же, а цифра помечается
    как «после подгонки».
- **Слепые авторы и аннотаторы** видят только `blind/spec_v*.json` и строки без меток.
- **Правила сопоставителя v2** подгонялись только по авторам r6 и cs. Автор stt — отложенная проверка.
  Если править правила дальше, для честной цифры нужны новые слепые строки.
- **Порог и гейт** выбираются по out-of-fold, а не по тестовым строкам.
- **`COOP_TAG`** выбирает набор данных и seed-команд:

  | значение | что это |
  |---|---|
  | не задан | исследование v2 |
  | `v21` | боевой бот v2 |
  | `v3` | строки и seed-команды с местами |

  От тега зависят имена файлов результатов.

## 7. Решения, принятые по умолчанию (владелец может поменять)

- Информационные коллауты («two on red stairs») остаются NONE. Место при этом находится и передаётся
  планировщику как контакт.
- «Go to the roof» без слов про верёвку — MOVE_TO, а не RAPPEL (`blind/spec_v3.json`).
- Зоны `upstairs` / `downstairs` (этаж выше или ниже бота) и `second floor` добавлены сверх списка
  владельца.
- «first floor» и «ground floor» — одна зона.
