# Снимок проекта: ко-оп бот на DeBERTa-v3

Снимок обновлён 2026-10-04 на MacBook (Apple M5 Pro, 24 ГБ). Первая версия снимка сделана 2026-10-03 на
рабочей машине (Windows, RTX 4090). Здесь описано, где что лежит, как запустить бота, в каком состоянии
работа и что делать дальше.

## 1. Где что лежит

| что | где | размер |
|---|---|---|
| код, данные, логи, документы, тестовые файлы паритета | git; корень репозитория — эта папка (`project_synth/`) | ~135 МБ |
| веса ботов v2 и v1 (`*.safetensors`, `*.onnx`) | архив `coop-bot-models.tar` с рабочей машины | 5,6 ГБ |
| веса финальной модели v3 | только на MacBook: `models/coop-deberta-v3-ens3-v3/` | 4,2 ГБ |

- Весов в git нет: файлы по 738 МБ не проходят лимит GitHub (100 МБ). В `.gitignore` стоят
  `*.safetensors` и `*.onnx`.
- После клонирования веса кладутся в те же папки: `models/<бот>/seed{0,1,2}/model.safetensors` и
  `models/<бот>/cpp/model{0,1,2}.onnx` (у v1 — `model.safetensors` и `cpp/model.onnx`).
- **Про v3 в репозитории.** `bot_config.json`, `cpp/intent_config.json`, `cpp/golden.jsonl` и тестовые
  файлы в `models/coop-deberta-v3-ens3-v3/` описывают модель, обученную на MacBook (MPS). На рабочей машине
  есть своя финальная v3, обученная на CUDA: это другая модель, её вероятности с этими файлами не
  совпадут. Для неё нужно заново выполнить экспорт и генерацию тестов (раздел 5, шаг 4).
- В репозитории нет:
  - экспериментов с laya, Qwen и ollaya (`models/coop-laya-ft`, остальные папки `scripts/`);
  - ONNX Runtime и папки `build/` (скачиваются и собираются на месте, раздел 3).

## 2. Python-окружение и бот

```
python3.11 -m venv .venv && source .venv/bin/activate
pip install torch "transformers==5.17.0" "tokenizers==0.23.2" onnxruntime onnx scikit-learn numpy sentencepiece
cd scripts/coop
python coop_bot.py                                             # бот v2 (модель по умолчанию)
python coop_bot.py --model ../../models/coop-deberta-v3-ens3-v3   # финальная v3
```

- Версии `transformers` и `tokenizers` — те, на которых всё обучалось и проверялось.
- `sentencepiece` нужен только для обучения: `train_v2.py` берёт токенизатор и веса
  `microsoft/deberta-v3-base` с HF Hub (нужен интернет или прогретый кэш). Боту он не нужен.
- На MacBook окружение создано через `uv venv --python 3.11 .venv`; туда же поставлены `cmake` и `ninja`
  (`pip install cmake ninja`), потому что в системе их не было.
- Команды в чате: `/why`, `/t 0.6`, `/q`. Под ответом бот печатает места, которые нашёл в реплике
  (строка `place:`), а при исполнении отложенного приказа — место и «other» этого приказа.

## 3. C++-движок

Собран и проверен на macOS arm64 (AppleClang 21, libc++). Для сборки правок в исходниках не понадобилось.

```
cd cpp/coop_intent/third_party
curl -LO https://github.com/microsoft/onnxruntime/releases/download/v1.30.0/onnxruntime-osx-arm64-1.30.0.tgz
tar -xzf onnxruntime-osx-arm64-1.30.0.tgz
xattr -dr com.apple.quarantine onnxruntime-osx-arm64-1.30.0     # если macOS блокирует библиотеку
cd ..
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/coop_cli --threads 1                                              # чат, бот v2
./build/coop_cli --model-dir ../../models/coop-deberta-v3-ens3-v3/cpp      # чат, финальная v3
```

Проверки паритета с Python-ботом (`--model-dir` выбирает бота; первая строка вывода называет модель):

## 4. Состояние работы

**Бот v2 — в игре, модель по умолчанию**
- 24 приказа, включая TAKE_COVER и OPEN. Ансамбль из трёх DeBERTa-v3-base, гейт по семейству,
  порог 0.58: `models/coop-deberta-v3-ens3-v2`.
- Кросс-валидация по авторам: попадание 90.5%, действия из чужого семейства 1.9%.
- Подробности: `COOP-BOT.md` (раздел «v2») и `DEBERTA-BOT.md` (раздел 11).

**v3: места на карте (коллауты)**

Идея: названия мест модель не учит. Их находит словарь с правилами и отдаёт планировщику цель.

- `scripts/coop/locations.json` — словарь; `scripts/coop/locations.py` — сопоставитель; C++-порт —
  `cpp/coop_intent/src/locations.cpp`.
- `python locations.py --dev` на замороженных правилах v2: 254 строки, 5 известных промахов, код возврата 1.
  Регрессия — это любое изменение этого списка.
- Слепые данные: `blind/v3`, `annot/v3` — 3 автора по 50 строк, по 2 аннотатора на автора.

Во всех цифрах ниже «критерий» = попадание − 2 × чужое семейство. Интервалы — парный бутстрэп по строкам.

Сопоставитель, точная цель (объект, уточнение, зона) на 150 слепых строках. Роли и пометы не оцениваются.

| правила | результат |
|---|---|
| v1, заморожены до появления строк | 132/150 = 88.0% (r6 43, cs 44, stt 45 из 50) |
| v2, после подгонки по авторам r6 и cs | 145/150 = 96.7%; на r6 и cs 98/100 |
| v2 на отложенном авторе stt | 47/50 = 94% [84–98], было 45/50 |

- Отложенный stt — не независимая проверка правил v2: обе его новые строки повторяют идиомы авторов
  подгонки («ping is through the roof», «my main»). Три собственных промаха stt не изменились.
- Авторы слепых строк видели названия мест в `blind/spec_v3.json`. Цифры меряют правила на канонических
  названиях: место, названное не по словарю, не находится («second story», «the rough»).
- Файлы правил v1 не сохранились: 88.0% подтверждается только логом `eval_v3_rules_v1.log`.

Классификатор на 150 слепых строках с местами (`eval_v3.log`, `eval_v3_review.log`):

| | попадание | точный приказ | чужое семейство | критерий |
|---|---|---|---|---|
| бот v2, сырая строка | 83.3 | 82.0 | 3.3% | 76.7 |
| дообученный ансамбль, гейт top | 90.0 | 89.3 | 1.3% | 87.3 |
| дообученный ансамбль, гейт family | 90.7 | 90.0 | 1.3% | 88.0 |

- Разница с ботом v2 по критерию: +10.7 [+3.3, +18.7] (top) и +11.3 [+4.0, +19.3] (family).
  По одному попаданию: +6.7 [+1.3, +12.7] и +7.3 [+2.0, +13.3].
- Почти весь выигрыш даёт автор r6: попадание 39 → 49 из 50; у cs 46 → 46, у stt 40 → 41. Без r6
  разница по попаданию +0.0 / +1.0, интервал включает ноль. Сравнение при этом не в пользу дообученной
  модели: бот v2 обучался на старых строках всех трёх авторов, а модель фолда своего автора не видела.
- На 90 новых по формулировке строках разница по критерию +8.9 [+1.1, +17.8] / +10.0 [+2.2, +18.9].
- Приказ и место верны вместе на 132/150 = 88.0% (бот v2: 121/150); на авторе stt — 39/50.
- На 483 старых строках критерий не изменился: 0.0 [−3.9, +4.1] (top) / −0.2 [−4.3, +3.7] (family).
  Потеря больше ~4 пунктов исключена; ответ меняется на 38–39 строках.
- Вырезание уточнений («north», «red») перед классификатором не помогло ни на одной строке: меняются
  3 ответа из 150, все в худшую сторону. Модель читает сырую строку.

**Финальная модель v3 — обучена, экспортирована, проверена; по умолчанию не включена**

- `models/coop-deberta-v3-ens3-v3`: три DeBERTa-v3-base, гейт по семейству, порог 0.60 (по out-of-fold
  на 633 строках: критерий 569 у family против 560 у top).
- Обучена на MacBook (MPS) командой `COOP_TAG=v3 python train_v2.py final ens3`: 18 обучений за
  53 мин 20 с, около 178 с на обучение, пик памяти 9,0 ГБ. На RTX 4090 это около 25 минут.
- Все цифры кросс-валидации получены на моделях, обученных на CUDA. Проверка MPS перед обучением:
  прямой проход совпадает с CPU (расхождение до 1.2e-5 на 762 строках); три модели «без автора stt» на
  MPS дают результат в пределах разброса между сидами по argmax. На рабочих порогах того же фолда у MPS
  больше чужого семейства (8 против 4 строк из 211 у top, 10 против 6 у family); на одном фолде это не
  значимо, но и равенством не является.
- ONNX совпадает с PyTorch на 1062/1062 строках. Проверки C++ — в таблице раздела 3.
- На 80 строках свежего автора из ревью (один автор-ИИ, он же единственный разметчик, слепота частичная)
  финальная v3 лучше бота v2 на строках с местами: попадание 59/60 против 55/60; на обычных приказах
  20/20 у обеих.

**Известное поведение финальной v3** (`probe_v3.log`; пробы не слепые, чтение строк — разработчика)

- **Коллаут о дыме исполняется как приказ.** «<место> is smoked»: v3 бросает дым на 47 названиях из 47
  с уверенностью 0.95–1.00, бот v2 — на 7 из 47. В обучении слово «smoked» есть только в двух строках, и
  обе — приказы SMOKE; среди слепых NONE-строк таких коллаутов нет, поэтому цифра «действует на
  не-приказ» этот класс не покрывает.
- **«<место> clear» без связки исполняется как ENTRY**: v3 на 27 названиях из 30, бот v2 на 19 из 30.
  Со связкой («X is clear») обе модели молчат. На названиях вне словаря и без места («room clear») так
  же ведёт себя и v2.
- **Крыша.** «to / up to the roof» теперь MOVE_TO. «on / onto the roof» и голое «roof» остаются RAPPEL
  (сетка глагол × предлог: v3 18 из 42, v2 40 из 42). Причина: в `seed_commands_v3.json` из v21
  унаследованы seed-команды «get on the roof» и «go roof» с меткой RAPPEL, против `spec_v3.json`.
  Дообучение ошибку «get up on the roof» не чинит: с отложенным автором ансамбль отвечает RAPPEL, а
  финальная модель отвечает MOVE_TO только потому, что эта строка есть в её обучении.
- **Регистр.** Модель различает регистр и видела только строчные реплики. Seed-команды заглавными
  буквами дают действие из чужого семейства на 10 из 233 (v2: 8): FLANK → FRAG или FLASH, RAPPEL → FRAG.

**Ревью v3 — проведено**

- Семь рецензентов по направлениям, каждая находка перепроверена одним или двумя независимыми
  проверяющими, затем четыре рецензента по пробелам. 73 находки, ни одна не опровергнута целиком.
- Всё лежит в `scripts/coop/review_v3/`: `FINDINGS.md` (каждая находка с вердиктами), `findings.json`,
  строки свежего автора. Цифры ревью воспроизводят `eval_v3_review.py` и `probe_v3.py`.
- Проверено и подтверждено: хронология заморозки; пороги и гейт выбираются только по out-of-fold;
  цифры `eval_v3.log` пересчитаны независимо; C++-порт сопоставителя совпал с Python на 210 695 новых
  строках и на 60 случайных словарях; санитайзеры чисты.

Исправлено по ревью (замороженное не тронуто, все записи в `frozen.txt`):

- отложенный приказ хранит и слово «other», в записи бота есть исполненный приказ (`coop_bot.py`,
  `bot_brain.cpp`); прежние решения бота не изменились;
- загрузка словаря в C++ не зависит от локали (на libc++ при десятичной запятой словарь не грузился);
- `LocationMatcher::Init` отвергает неизвестный список слов, как Python;
- `coop_cli` называет проверяемую модель, снова читает тестовые файлы v1, сравнивает новые поля;
- `gen_tests.py`: шаг «ровно под порогом» был неверен для порога 0.60; шагов решений стало 138 (было 52),
  и они ловят все 72 намеренные поломки `BotBrain::Decide`, сделанные для проверки тестов;
- `train_v2.py`: выбор устройства (cuda, mps, cpu), устройство в `bot_config.json`, out-of-fold
  вероятности финальной модели сохраняются в `results_<тег>_final_oof.json` (со следующего обучения);
- `v3_noharm.py` снова запускается.

## 6. Правила, которых держится проект

- **Заморозка.**
  - Спецификация, seed-команды и правила фиксируются до появления тестовых строк. Хэши и порядок
    записаны в `scripts/coop/frozen.txt`.
  - Если что-то правится после просмотра тестовых строк, это записывается там же, а цифра помечается
    как «после подгонки».
- **Слепые авторы и аннотаторы** видят только `blind/spec_v*.json` и строки без меток. Авторы получают
  ещё роль и квоту по видам строк; этот текст задания в архиве не сохранён.
- **Правила сопоставителя v2** подгонялись только по авторам r6 и cs. Автор stt отложен, но делит с
  ними идиомы (раздел 4). Если править правила дальше, для честной цифры нужны новые слепые строки.
- **Строки ревью** (`review_v3/fresh_author.json`, пробы `probe_v3.py`) уже просмотрены. По ним нельзя
  подгонять правила, seed-команды и пороги и нельзя мерить результат подгонки.
- **Порог и гейт** выбираются по out-of-fold, а не по тестовым строкам.
- **`COOP_TAG`** выбирает набор данных и seed-команд:

  | значение | что это |
  |---|---|
  | не задан | исследование v2 |
  | `v21` | боевой бот v2 |
  | `v3` | строки и seed-команды с местами |

  От тега зависят имена файлов результатов.
- **Обучение на Mac.** `train_v2.py` сам выбирает `mps`; `COOP_DEVICE=cpu|mps|cuda` задаёт устройство
  явно. Долгие прогоны запускать через `caffeinate -i`, иначе MacBook засыпает.

## 7. Решения

**Принятые по умолчанию (владелец может поменять)**

- Информационные коллауты («two on red stairs») остаются NONE. Место при этом находится и передаётся
  планировщику как контакт. Исключения в финальной v3 — коллауты о дыме и «clear» (раздел 4).
- «Go to the roof» без слов про верёвку — MOVE_TO, а не RAPPEL (`blind/spec_v3.json`). В модели это
  пока верно только для формулировок с «to the roof».
- Зоны `upstairs` / `downstairs` (этаж выше или ниже бота) и `second floor` добавлены сверх списка
  владельца.
- «first floor» и «ground floor» — одна зона.
- Очередь отложенного приказа — одна ячейка. Любая реплика WAIT («not yet», «hold on») сбрасывает
  приказ вместе с местом: по спецификации WAIT — и пауза, и отмена. Новый приказ «on my go» заменяет
  прежний.
- Бот отдаёт приказ и место независимо и не сверяет их между собой (VAULT_WINDOW с дверью в цели
  возможен: 1 строка из 150).

**Открытые решения (ждут владельца)**

1. Набор seed-команд v3.1 и переобучение (раздел 5, шаг 2) — или выпуск v3 как есть, с известным
   поведением из раздела 4.
2. Когда переключать модель по умолчанию на v3: сейчас или после шага 2.
3. Правила сопоставителя v3. Находки ревью, каждая требует новых слепых строк:
   - «stack up on <место>», «squad up», «awp» дают цели роль «враг»;
   - формы без апострофа («theyre», «hes») не дают роль, и место врага становится целью бота;
   - роль у основной цели означает то «действуй здесь», то «сюда не ходи»: на приказах она верна в
     13 случаях из 21, планировщик не может читать её как запрет;
   - цвет перед любым существительным вне списка из 19 слов становится лестницей («red car»).
4. WAIT для отложенного приказа: пауза или отмена.
5. Защита от регистра (перевод реплики заглавными буквами в строчные) и ограничение длины строки перед
   сопоставителем: его время растёт как куб числа мест в строке, обычная реплика занимает микросекунды.
