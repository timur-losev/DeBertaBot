# Состояние проекта: ко-оп бот на DeBERTa-v3

Обновлено 2026-10-04 на рабочей машине (Windows, RTX 4090) после слияния двух линий работы: правок с
MacBook (Apple M5 Pro: финальная модель v3, ревью, исправления движка) и правок рабочей машины (правила
мест v3, набор seed-команд v31, C++-порт правил). Здесь описано, где что лежит, как запустить бота, в
каком состоянии работа и что делать дальше.

**Ближайший шаг — обучение модели v31 на MacBook: раздел 5.**

## 1. Где что лежит

| что | где | размер |
|---|---|---|
| код, данные, логи, документы, тестовые файлы паритета | git, корень репозитория | ~140 МБ |
| веса ботов v2 и v1 (`*.safetensors`, `*.onnx`) | архив `coop-bot-models.tar` с рабочей машины | 5,6 ГБ |
| веса финальной модели v3 | только на MacBook: `models/coop-deberta-v3-ens3-v3/` | 4,2 ГБ |

- Весов в git нет: файлы по 738 МБ не проходят лимит GitHub (100 МБ). В `.gitignore` стоят
  `*.safetensors` и `*.onnx`.
- После клонирования веса кладутся в те же папки: `models/<бот>/seed{0,1,2}/model.safetensors` и
  `models/<бот>/cpp/model{0,1,2}.onnx` (у v1 — `model.safetensors` и `cpp/model.onnx`).
- **Про v3 в репозитории.** `bot_config.json`, `cpp/intent_config.json`, `cpp/golden.jsonl` и тестовые
  файлы в `models/coop-deberta-v3-ens3-v3/` описывают модель, обученную на MacBook (MPS). На рабочей
  машине есть своя v3, обученная на CUDA (порог 0.52): это другая модель, в репозитории её нет. Её лог
  обучения — `scripts/coop/train_v3_final_ens3_cuda.log`.
- В репозитории нет:
  - экспериментов с laya, Qwen и ollaya (`models/coop-laya-ft`, остальные папки `scripts/`);
  - ONNX Runtime и папки `build/` (скачиваются и собираются на месте, раздел 3).

## 2. Python-окружение и бот

```
python3.11 -m venv .venv && source .venv/bin/activate
pip install torch "transformers==5.17.0" "tokenizers==0.23.2" onnxruntime onnx scikit-learn numpy sentencepiece
cd scripts/coop
python coop_bot.py                                             # бот v2 (модель по умолчанию)
python coop_bot.py --model ../../models/coop-deberta-v3-ens3-v3   # финальная v3
```

- Версии `transformers` и `tokenizers` — те, на которых всё обучалось и проверялось.
- `sentencepiece` нужен только для обучения: `train_v2.py` берёт токенизатор и веса
  `microsoft/deberta-v3-base` с HF Hub (нужен интернет или прогретый кэш). Боту он не нужен.
- На MacBook окружение создано через `uv venv --python 3.11 .venv`; туда же поставлены `cmake` и `ninja`
  (`pip install cmake ninja`).
- Команды в чате: `/why`, `/t 0.6`, `/q`. Под ответом бот печатает места, которые нашёл в реплике
  (строка `place:`), а при исполнении отложенного приказа — место и «other» этого приказа.
- **Модель по умолчанию** задана в одном месте для всех Python-инструментов: `DEFAULT` в
  `scripts/coop/bots.py`. Для C++ — `COOP_MODEL_DIR` в `cpp/coop_intent/CMakeLists.txt`.

## 3. C++-движок

Собран и проверен на Windows (MSVC) и на macOS arm64 (AppleClang 21, libc++).

```
cd cpp/coop_intent/third_party
curl -LO https://github.com/microsoft/onnxruntime/releases/download/v1.30.0/onnxruntime-osx-arm64-1.30.0.tgz
tar -xzf onnxruntime-osx-arm64-1.30.0.tgz
xattr -dr com.apple.quarantine onnxruntime-osx-arm64-1.30.0     # если macOS блокирует библиотеку
cd ..
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/coop_cli --threads 1                                              # чат, бот v2
./build/coop_cli --model-dir ../../models/coop-deberta-v3-ens3-v3/cpp      # чат, финальная v3
```

Проверки паритета с Python-ботом (`--model-dir` выбирает бота; первая строка вывода называет модель):

```
./build/coop_cli --tokenizer-tests     # токенизатор и регэкспы, без модели
./build/coop_cli --location-tests      # места в реплике, без модели
./build/coop_cli --gate-tests
./build/coop_cli --decide-tests
./build/coop_cli --golden              # с моделью: вероятности против PyTorch
./build/coop_cli --dialogue
```

## 4. Состояние работы

Во всех цифрах ниже «критерий» = попадание − 2 × чужое семейство. Интервалы — парный бутстрэп по строкам.

**Бот v2 — в игре, модель по умолчанию**
- 24 приказа, включая TAKE_COVER и OPEN. Ансамбль из трёх DeBERTa-v3-base, гейт по семейству,
  порог 0.58: `models/coop-deberta-v3-ens3-v2`.
- Кросс-валидация по авторам: попадание 90.5%, действия из чужого семейства 1.9%.
- Скорость на рабочей машине: 39.7 мс на трёх ядрах (перемерено 2026-10-04; прежние 61 мс — медленный
  прогон).
- Подробности: `COOP-BOT.md` (раздел «v2») и `DEBERTA-BOT.md` (раздел 11).

**Места на карте: сопоставитель, правила v3**

Названия мест модель не учит. Их находит словарь с правилами и отдаёт планировщику запись: все места
реплики, чьё каждое и какое из них цель бота. Сопоставитель работает с любой моделью, в том числе с
ботом v2.

- `scripts/coop/locations.json` — словарь; `scripts/coop/locations.py` — правила; C++-порт —
  `cpp/coop_intent/src/locations.cpp`. Прежние наборы правил лежат в `scripts/coop/rules/v1` и `v2`.
- `python locations.py --dev`: 254 строки, 3 известных промаха, код возврата 1. Регрессия — любое
  изменение этого списка.

Точная цель (объект, уточнение, зона) на 150 слепых строках и «пригодная цель» на 123 приказах из них.
Пригодная — точная, без роли и без пометы «не уверен», то есть планировщик может по ней действовать.

| правила | точная цель | пригодная на приказах | статус |
|---|---|---|---|
| v1, заморожены до появления строк | 132/150 = 88.0% | 103/123 = 83.7% | **слепая цифра** |
| v2, после чтения строк r6 и cs | 145/150 = 96.7% | 112/123 = 91.1% | подогнано |
| v3, после двух ревью | 147/150 = 98.0% | 122/123 = 99.2% | подогнано |

- У правил v2 и v3 слепой цифры на своих строках проекта нет. Отложенный автор stt для v2 независимой
  проверкой не был: обе его новые строки повторяют идиомы авторов подгонки.
- Что исправляют правила v3 (находки обоих ревью):
  - роли срабатывали на обычных приказах: «cover me from the east window», «stack up on the north
    door», «north door is yours, hold it»;
  - «on second thought» читалось как второй этаж;
  - этаж приклеивался к объекту следующей фразы;
  - формы без апострофа («hes», «theyre») не давали роли;
  - «you take the south one» теперь даёт дверь, а не просто направление.
- Косвенные проверки правил v3 (`python rules/check.py`, лог `rules/check.log`):
  - три критика писали свои строки против v3. Из 213 обычных реплик, написанных до просмотра
    результатов, ошибок было 4 (1.9%): везде не хватало роли у единственного места, неверной цели не
    было. После правки по строкам критиков: обычные 395 строк — 0 неверных целей, 5 неверных ролей;
    строки «как из распознавания речи» (246) — 37 неверных целей; состязательные (242) — 17 неверных
    целей и 43 неверные роли. Последние два набора — известные пределы правил;
  - 80 строк свежего автора из ревью на Mac (один автор-ИИ, он же разметчик; при написании правил v3
    эти строки не читались): точная цель 76 / 77 / 78 из 80 и пригодная 65 / 66 / 68 из 70 для
    v1 / v2 / v3.
- Место, названное не по словарю, не находится («second story», «the rough»).

**Классификатор на 150 слепых строках с местами** (`eval_v3.log`, `eval_v3_review.log`; модели обучены
на CUDA)

| | попадание | точный приказ | чужое семейство | критерий |
|---|---|---|---|---|
| бот v2, сырая строка | 83.3 | 82.0 | 3.3% | 76.7 |
| дообученный ансамбль, гейт top | 90.0 | 89.3 | 1.3% | 87.3 |
| дообученный ансамбль, гейт family | 90.7 | 90.0 | 1.3% | 88.0 |

- Разница с ботом v2 по критерию: +10.7 [+3.3, +18.7] (top) и +11.3 [+4.0, +19.3] (family).
  По одному попаданию: +6.7 [+1.3, +12.7] и +7.3 [+2.0, +13.3].
- Почти весь выигрыш даёт автор r6: попадание 39 → 49 из 50; у cs 46 → 45–46, у stt 40 → 41. Без r6
  интервал включает ноль. У r6 строки v3 написаны с заглавными буквами и пунктуацией, в отличие от

- На 483 старых строках критерий не изменился: 0.0 [−3.9, +4.1] (top) / −0.2 [−4.3, +3.7] (family).

**Финальная модель v3 — обучена, экспортирована, проверена; по умолчанию не включена**

- `models/coop-deberta-v3-ens3-v3`: три DeBERTa-v3-base, гейт по семейству, порог 0.60 (по out-of-fold
  на 633 строках: критерий 569 у family против 560 у top).
- Обучена на MacBook (MPS) командой `COOP_TAG=v3 python train_v2.py final ens3`: 18 обучений за
  53 мин 20 с, около 178 с на обучение, пик памяти 9,0 ГБ. На RTX 4090 это около 25 минут.
- Проверка MPS перед обучением: прямой проход совпадает с CPU (расхождение до 1.2e-5 на 762 строках);
  три модели «без автора stt» на MPS дают результат в пределах разброса между сидами по argmax. На
  рабочих порогах того же фолда у MPS больше чужого семейства (8 против 4 строк из 211 у top, 10
  против 6 у family); на одном фолде это не значимо, но и равенством не является.

**Известное поведение финальной v3** (`probe_v3.log`; пробы не слепые)

- **Коллаут о дыме исполняется как приказ.** «<место> is smoked»: v3 бросает дым на 47 названиях из 47,
  бот v2 — на 7 из 47.
- **«<место> clear» без связки исполняется как ENTRY**: v3 на 27 названиях из 30, бот v2 на 19 из 30.
- **Крыша.** «to / up to the roof» — MOVE_TO. «on / onto the roof» и голое «roof» остаются RAPPEL: в
  `seed_commands_v3.json` из v21 унаследованы «get on the roof» и «go roof» с меткой RAPPEL.
- **«take blue» → ENTRY**, а «take blue stairs» → MOVE_TO: в seed-команды попали только формы со словом
  «stairs» (150 сочетаний шаблона и места из 486).
- **Регистр.** Модель различает регистр и видела в основном строчные реплики.

**Набор seed-команд v31 — готов, модель на нём не обучена**

`scripts/coop/make_seeds_v31.py` → `seed_commands_v31.json` (491 команда; у v3 было 383), тег
`COOP_TAG=v31`:
- «get on the roof» и «go roof» перенесены в MOVE_TO;
- каждый шаблон приказа заполнен местами каждого вида, который он допускает (253 сочетания из 582),
  включая голые названия («take white»);
- в NONE добавлены шаблоны коллаутов о состоянии: «<место> is smoked», «<место> clear» и подобные, и
  пять коллаутов без места («it's smoked», «all clear»).

Набор написан после просмотра слепых строк и проб. Цифры модели v31 на этих строках и пробах надо
помечать «после подгонки».

**Ревью v3**

- На MacBook: семь рецензентов по направлениям, проверка каждой находки, четыре рецензента по пробелам.
  73 находки: `scripts/coop/review_v3/` (`FINDINGS.md`, `findings.json`, строки свежего автора),
  `eval_v3_review.py`, `probe_v3.py`.
- На рабочей машине: четыре рецензента и четыре проверяющих, 47 находок; затем три критика правил v3
  (`scripts/coop/rules/critic_v3/`).
- Исправлено по обоим ревью (все записи в `frozen.txt`):
  - правила мест v3 и их C++-порт; у цели больше нет позиций токенов;
  - отложенный приказ хранит место и слово «other»; в записи бота есть исполненный приказ;
  - NaN вместо вероятностей даёт «say again» (Python и C++);
  - `BotBrain::Init` сбрасывает прежний сопоставитель и очередь;
  - загрузчик `coop_cli` отвергает конфигурацию с сообщением: нет ключа, лишний или недостающий раздел
    словаря, повтор ключа, пустой `lone`;
  - «on one of the windows» больше не ставит приказ в очередь (регэксп времени);
  - загрузка словаря в C++ не зависит от локали;
  - `gen_tests.py`: 138 шагов решений из файла и 2 встроенных (NaN); 12000 сгенерированных строк для
    мест; режим `--no-model`;
  - `export_cpp.py` сам берёт тег данных из `bot_config.json` модели;
  - `train_v2.py`: выбор устройства, `smoke`, `--reuse-gate`, out-of-fold вероятности финальной модели
    сохраняются в `results_<тег>_final_oof.json`;
  - `eval_v3.py`: «пригодная цель», разбивка выигрыша по авторам, архивные правила (`--rules v1`).

## 5. Что делать дальше

1. **На MacBook после `git pull`: пересобрать C++ и прогнать проверки для v3 и v2.**
   ```
   cd cpp/coop_intent && cmake --build build
   for t in --tokenizer-tests --location-tests --gate-tests --decide-tests --golden --dialogue; do
     ./build/coop_cli --model-dir ../../models/coop-deberta-v3-ens3-v3/cpp $t | tail -1
     ./build/coop_cli $t | tail -1
   done
   ```
   Ожидаемые числа — в таблице раздела 3. Если `--dialogue` для v3 не сойдётся, перегенерировать её
   тестовые файлы уже с весами: `python cpp/coop_intent/tools/gen_tests.py models/coop-deberta-v3-ens3-v3`.
2. **Обучить модель v31 на MacBook.**
   ```
   cd scripts/coop
   python train_v2.py smoke                         # минута: устройство mps работает
   COOP_TAG=v31 caffeinate -i python train_v2.py final ens3 2>&1 | tee train_v31_final_ens3.log
   ```
   - 18 обучений: 15 для out-of-fold (порог и гейт) и 3 финальных. Обучающих строк 1124 против 1016
     у v3, так что ждать около часа (v3 заняла 53 минуты).
   - Результат: `models/coop-deberta-v3-ens3-v31/` и `results_v31_final_oof.json`.
   - Сокращённый вариант — только 3 финальных обучения, порог и гейт берутся у v3 и под новый набор не
     подбираются: добавить `--reuse-gate ../../models/coop-deberta-v3-ens3-v3/bot_config.json`.
3. **Экспорт и проверки новой модели.**
   ```
   python export_cpp.py ../../models/coop-deberta-v3-ens3-v31
   python check_onnx.py ../../models/coop-deberta-v3-ens3-v31
   python ../../cpp/coop_intent/tools/gen_tests.py ../../models/coop-deberta-v3-ens3-v31
   cd ../../cpp/coop_intent
   for t in --tokenizer-tests --location-tests --gate-tests --decide-tests --golden --dialogue; do
     ./build/coop_cli --model-dir ../../models/coop-deberta-v3-ens3-v31/cpp $t | tail -1
   done
   ```
   `export_cpp.py` сам выставит тег `v31` по `bot_config.json`; `golden.jsonl` будет на 1170 строк.
4. **Посмотреть, взялись ли исправления** (это проверка починки, а не слепая оценка):
   ```
   cd scripts/coop
   python probe_v3.py ../../models/coop-deberta-v3-ens3-v31 ../../models/coop-deberta-v3-ens3-v3 results_v31_probe.json > probe_v31.log
   ```
   В выводе первая модель подписана «v3», вторая «v2». Смотреть: «<место> is smoked», «<место> clear»,
   сетку с крышей, «take <цвет>».
5. **Кросс-валидация v31 — по желанию** (54 обучения, на MacBook по оценке 2,5–3 часа; на RTX 4090 —
   около 35 минут в три процесса):
   ```
   COOP_TAG=v31 caffeinate -i python train_v2.py cv base 2>&1 | tee train_v31_cv.log
   COOP_TAG=v31 python eval_v3.py > eval_v31.log        # нужен scikit-learn
   ```
   Она покажет, не стало ли хуже на 633 строках (сравнение с исследованиями v3 и v21 печатается само).
6. **Вторая слепая партия строк (`blind/v3b`)** — единственный способ получить честную цифру для
   правил v3 и модели v31. Скрипты готовы: `v3b_shipped.py` (вероятности всех обученных ботов) и
   `eval_v3b.py` (правила v1–v3 и боты на строках, под которые никто не подгонялся). Самих строк ещё
   нет: их пишут три слепых автора и шесть аннотаторов (девять агентов), как для `blind/v3`. В партию
   стоит включить коллауты о состоянии.
7. **Модель по умолчанию.** Сейчас везде v2. Переключение — `DEFAULT` в `scripts/coop/bots.py` и
   `COOP_MODEL_DIR` в `CMakeLists.txt` (плюс кэш CMake, раздел 3). Разумно переключать на v31 после
   шагов 3–4.
8. **Этап 2 — плагин UE5.** План в `cpp/coop_intent/README.md` (модель через NNE, регэкспы через ICU по
   ASCII-«тени», места — GameplayTags на акторах уровня, договор с планировщиком о ролях и пометах).

Если поменялся только словарь мест, правила или регэкспы, переобучать не нужно. Для каждой папки бота:

```
python scripts/coop/locations.py --dev
python scripts/coop/export_cpp.py models/<бот> --config-only
python cpp/coop_intent/tools/gen_tests.py models/<бот>         # --no-model, если весов этого бота на машине нет
```

## 6. Правила, которых держится проект

- **Заморозка.**
  - Спецификация, seed-команды и правила фиксируются до появления тестовых строк. Хэши и порядок
    записаны в `scripts/coop/frozen.txt`.
  - Если что-то правится после просмотра тестовых строк, это записывается там же, а цифра помечается
    как «после подгонки».
- **Слепые авторы и аннотаторы** видят только `blind/spec_v*.json` и строки без меток. Авторы получают
  ещё роль и квоту по видам строк.
- **Правила сопоставителя v2 и v3** написаны после чтения слепых строк v3. Строки критиков
  (`rules/critic_v3`) и регрессионный набор — материал для настройки, не тест.
- **Строки ревью** (`review_v3/fresh_author.json`, пробы `probe_v3.py`) уже просмотрены. По ним нельзя
  мерить результат подгонки; набор seed-команд v31 написан с оглядкой на пробы.
- **Порог и гейт** выбираются по out-of-fold, а не по тестовым строкам.
- **`COOP_TAG`** выбирает набор данных и seed-команд:

  | значение | что это |
  |---|---|
  | не задан | исследование v2 |
  | `v21` | боевой бот v2 |
  | `v3` | строки и seed-команды с местами (исследование v3 и финальная модель v3) |
  | `v31` | те же строки, набор seed-команд v31, независимое перечитывание строк r6 |

  От тега зависят имена файлов результатов и папка модели (`coop-deberta-v3-ens3-<тег>`).
- **Обучение на Mac.** `train_v2.py` сам выбирает `mps`; `COOP_DEVICE=cpu|mps|cuda` задаёт устройство
  явно. Долгие прогоны запускать через `caffeinate -i`, иначе MacBook засыпает.

## 7. Решения

**Принятые по умолчанию (владелец может поменять)**

- Информационные коллауты («two on red stairs») остаются NONE. Место при этом находится и передаётся
  планировщику как контакт.
- «Go to the roof» без слов про верёвку — MOVE_TO, а не RAPPEL (`blind/spec_v3.json`). В модели v3 это
  верно только для формулировок с «to the roof»; набор v31 это исправляет.
- «take <цвет>» — MOVE_TO к лестнице этого цвета. «take main» в seed-команды не включено: неясно,
  идти туда, держать или штурмовать.
- Зоны `upstairs` / `downstairs` (этаж выше или ниже бота) и `second floor` добавлены сверх списка
  владельца.
- «first floor» и «ground floor» — одна зона.
- Очередь отложенного приказа — одна ячейка. Любая реплика WAIT («not yet», «hold on») сбрасывает
  приказ вместе с местом: по спецификации WAIT — и пауза, и отмена. Новый приказ «on my go» заменяет
  прежний.
- Бот отдаёт приказ и место независимо и не сверяет их между собой (VAULT_WINDOW с дверью в цели
  возможен: 1 строка из 150).
- Договор с планировщиком: цель с ролью — не место назначения. Если роль есть у основной цели, значит,
  в реплике места назначения нет («get off the roof»). Помета «не уверен» означает низкую уверенность,
  а не отсутствие места.
- Сопоставитель читает последние 128 слов реплики и выбрасывает слова-паузы («uh», «um»).

**Открытые решения (ждут владельца)**

1. Когда переключать модель по умолчанию: на v31 после обучения и проверок (шаг 7 раздела 5) или
   оставить v2.
2. Заказывать ли вторую слепую партию строк (шаг 6 раздела 5). Без неё у правил v3 и модели v31 нет
   честной цифры.
3. WAIT для отложенного приказа: пауза или отмена.
4. Защита от регистра: переводить реплику в строчные буквы перед классификатором или нет. Строки
   автора r6 в v3 написаны с заглавными, и модель v3 на них обучена.
5. «on two» / «on three» читаются как счёт сигнала, даже когда игрок говорит об этаже.
