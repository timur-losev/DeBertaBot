(раздел 4, «Модель v4»), модель v51 с приказами огня, направлениями и командой «look at» (раздел 4,

MacBook (Apple M5 Pro: финальная модель v3, ревью, исправления движка) и правок рабочей машины (правила
мест v3, набор seed-команд v31, C++-порт правил). Здесь описано, где что лежит, как запустить бота, в

## 2. Python-окружение и бот

```
python3.11 -m venv .venv && source .venv/bin/activate
pip install torch "transformers==5.17.0" "tokenizers==0.23.2" onnxruntime onnx scikit-learn numpy sentencepiece
cd scripts/coop
python coop_bot.py                                             # бот v31 (по умолчанию); без её весов на машине — v2
python coop_bot.py --model ../../models/coop-deberta-v3-ens3-v2   # бот v2
python coop_bot.py --model ../../models/coop-deberta-v3-ens3-v3   # финальная v3
```

- Версии `transformers` и `tokenizers` — те, на которых всё обучалось и проверялось.
- `sentencepiece` нужен только для обучения: `train_v2.py` берёт токенизатор и веса
  `microsoft/deberta-v3-base` с HF Hub (нужен интернет или прогретый кэш). Боту он не нужен.
- На MacBook окружение создано через `uv venv --python 3.11 .venv`; туда же поставлены `cmake` и `ninja`
  (`pip install cmake ninja`).
- Команды в чате: `/why`, `/t 0.6`, `/q`. Под ответом бот печатает места, которые нашёл в реплике
  (строка `place:`), а при исполнении отложенного приказа — место и «other» этого приказа.
- **Модель по умолчанию — v31.** Она задана в одном месте для всех Python-инструментов: `DEFAULT` в
  `scripts/coop/bots.py`. Для C++ — `COOP_MODEL_DIR` в `cpp/coop_intent/CMakeLists.txt`. Если весов v31
  на машине нет, и Python-инструменты, и CMake берут бота v2 и сообщают об этом.

## 4. Состояние работы

Во всех цифрах ниже «критерий» = попадание − 2 × чужое семейство. Интервалы — парный бутстрэп по строкам.

  порог 0.58: `models/coop-deberta-v3-ens3-v2`.
- Кросс-валидация по авторам: попадание 90.5%, действия из чужого семейства 1.9%.
- Скорость на рабочей машине: 39.7 мс на трёх ядрах (перемерено 2026-10-04; прежние 61 мс — медленный
  прогон).
- Подробности: `COOP-BOT.md` (раздел «v2») и `DEBERTA-BOT.md` (раздел 11).

**Места на карте: сопоставитель, правила v3**

Названия мест модель не учит. Их находит словарь с правилами и отдаёт планировщику запись: все места
реплики, чьё каждое и какое из них цель бота. Сопоставитель работает с любой моделью, в том числе с
ботом v2.

- `scripts/coop/locations.json` — словарь; `scripts/coop/locations.py` — правила; C++-порт —
  `cpp/coop_intent/src/locations.cpp`. Прежние наборы правил лежат в `scripts/coop/rules/v1` и `v2`.
- `python locations.py --dev`: 254 строки, 3 известных промаха, код возврата 1. Регрессия — любое
  изменение этого списка.

Точная цель (объект, уточнение, зона) на 150 слепых строках и «пригодная цель» на 123 приказах из них.
Пригодная — точная, без роли и без пометы «не уверен», то есть планировщик может по ней действовать.

| правила | точная цель | пригодная на приказах | статус |
|---|---|---|---|
| v1, заморожены до появления строк | 132/150 = 88.0% | 103/123 = 83.7% | **слепая цифра** |
| v2, после чтения строк r6 и cs | 145/150 = 96.7% | 112/123 = 91.1% | подогнано |
| v3, после двух ревью | 147/150 = 98.0% | 122/123 = 99.2% | подогнано |

- У правил v2 и v3 слепой цифры на своих строках проекта нет. Отложенный автор stt для v2 независимой
  проверкой не был: обе его новые строки повторяют идиомы авторов подгонки.
- Что исправляют правила v3 (находки обоих ревью):
  - роли срабатывали на обычных приказах: «cover me from the east window», «stack up on the north
    door», «north door is yours, hold it»;
  - «on second thought» читалось как второй этаж;
  - этаж приклеивался к объекту следующей фразы;
  - формы без апострофа («hes», «theyre») не давали роли;
  - «you take the south one» теперь даёт дверь, а не просто направление.
- Косвенные проверки правил v3 (`python rules/check.py`, лог `rules/check.log`):
  - три критика писали свои строки против v3. Из 213 обычных реплик, написанных до просмотра
    результатов, ошибок было 4 (1.9%): везде не хватало роли у единственного места, неверной цели не
    было. После правки по строкам критиков: обычные 395 строк — 0 неверных целей, 5 неверных ролей;
    строки «как из распознавания речи» (246) — 37 неверных целей; состязательные (242) — 17 неверных
    целей и 43 неверные роли. Последние два набора — известные пределы правил;
  - 80 строк свежего автора из ревью на Mac (один автор-ИИ, он же разметчик; при написании правил v3
    эти строки не читались): точная цель 76 / 77 / 78 из 80 и пригодная 65 / 66 / 68 из 70 для

- **`COOP_TAG`** выбирает набор данных и seed-команд:

  | значение | что это |
  |---|---|
  | не задан | исследование v2 |
  | `v21` | боевой бот v2 |
  | `v3` | строки и seed-команды с местами (исследование v3 и финальная модель v3) |
  | `v31` | те же строки, набор seed-команд v31, независимое перечитывание строк r6; модель v31 |
  | `v5` | данные v31 под спецификацию на 27 намерений, строки и seed-команды v5; модель не обучалась |
  | `v51` | данные v5 под спецификацию на 29 намерений, строки и seed-команды v51; модель v51 |
  | `v52` | данные v51 под спецификацию на 32 намерения, строки и seed-команды v52; модель v52 |
  | `v53` | данные v52 под спецификацию на 33 намерения, строки и seed-команды v53; модель v53 |

  От тега зависят имена файлов результатов и папка модели (`coop-deberta-v3-ens3-<тег>`).

  Модель v4 — не значение `COOP_TAG`: её собирает `scripts/coop/stt/build_v4.py` на данных тега `v31`, к
  которым добавлены транскрипты Parakeet. Модели v51, v52 и v53 собирают `build_v51.py`, `build_v52.py` и
  `build_v53.py` на данных своих тегов с транскриптами; `train_v2.py` под тегами `v5`–`v53` не запускался.
- **Обучение на Mac.** `train_v2.py` сам выбирает `mps`; `COOP_DEVICE=cpu|mps|cuda` задаёт устройство
  явно. Долгие прогоны запускать через `caffeinate -i`, иначе MacBook засыпает.

## 7. Решения

**Принятые по умолчанию (владелец может поменять)**

- Информационные коллауты («two on red stairs») остаются NONE. Место при этом находится и передаётся
  планировщику как контакт.
- «Go to the roof» без слов про верёвку — MOVE_TO, а не RAPPEL (`blind/spec_v3.json`). В модели v3 это
  верно только для формулировок с «to the roof»; набор v31 это исправляет.
- «take <цвет>» — MOVE_TO к лестнице этого цвета. «take main» в seed-команды не включено: неясно,
  идти туда, держать или штурмовать.
- Зоны `upstairs` / `downstairs` (этаж выше или ниже бота) и `second floor` добавлены сверх списка
  владельца.
- «first floor» и «ground floor» — одна зона.
- Очередь отложенного приказа — одна ячейка. Любая реплика WAIT («not yet», «hold on») сбрасывает
  приказ вместе с местом: по спецификации WAIT — и пауза, и отмена. Новый приказ «on my go» заменяет
  прежний.
- Бот отдаёт приказ и место независимо и не сверяет их между собой (VAULT_WINDOW с дверью в цели
  возможен: 1 строка из 150).
- Договор с планировщиком: цель с ролью — не место назначения. Если роль есть у основной цели, значит,
  в реплике места назначения нет («get off the roof»). Помета «не уверен» означает низкую уверенность,
  а не отсутствие места.
- Сопоставитель читает последние 128 слов реплики и выбрасывает слова-паузы («uh», «um»).
- **Бот по умолчанию — v31** (решение владельца, 2026-10-04). Что это даёт против v2: места в приказах
  (на строках с местами +11 пунктов критерия, почти весь выигрыш у автора r6), крыша без верёвки —
  MOVE_TO, коллауты о дыме и «clear» не исполняются (v2 исполняет 7 из 47 и 19 из 30). Известная цена:
  слепой цифры для v31 нет; на старых строках потеря до ~5 пунктов не исключена; «clear main» больше не
  штурм; на заглавных буквах чужое семейство на 12 seed-командах из 233 против 8 у v2.

- **Голос** (решения владельца, 2026-10-07 и 2026-10-08): микрофон по кнопке; минимальный процессор
  i9-10900K; распознавание речи — Parakeet TDT 0.6B v2 через sherpa-onnx (около 0,7 ГБ памяти, около 200 мс
  на двух потоках после отпускания кнопки). Бота для этой цепочки учить на транскриптах Parakeet.
